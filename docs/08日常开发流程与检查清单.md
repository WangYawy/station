# 视音频数据采集站与监控管理平台 — 日常开发流程与检查清单

> 版本：0.1.0（基线）　配套：《开发规范》《Git 与协作规范》《CI 与发布规范》《部署与运维手册》

## 一、日常开发总览

```text
需求/缺陷 → 里程碑规划（M##）→ Spike 验证（高风险必做）
→ 编码 → 本地验证 → 提交 → CI → 发布/交付
```

每个里程碑（M##）都走完整闭环：方案文档 → 风险验证 → 实现 → 验证 → 提交 → 收尾。

## 二、环境准备

> 新成员首次搭建环境请先读《开发环境搭建与本地调试指南》（docs/09）：包含四个开发目标
> （桌面端 / 管理端后端 / 单机版 Web / 平台 Web）的完整本地启动与调试步骤。

| 项 | 要求 | 参考 |
| :--- | :--- | :--- |
| .NET SDK | 8.0.x | `Directory.Build.props` |
| Node.js | 满足 Vite 6 要求 | `station-web` / `station-platform-web` 的 `package.json` |
| pnpm | 9.x（`npm install -g pnpm` 或 `corepack enable`） | 根 `package.json` 的 `packageManager` 字段 |
| 数据库 | MySQL / PostgreSQL 至少一个本地实例；金仓按需 | docs/03（WSL2 + Kingbase）；MySQL/PG 可用 `docker compose -f deploy/platform/docker-compose.yml up -d mysql` 一键起 |
| 前端依赖 | 仓库根 `pnpm install`（一次性，pnpm workspace） | docs/09 |

### 常用命令

```powershell
# 后端
dotnet build .\Station.Desktop.sln -c Release
dotnet build .\Station.Platform.sln -c Release

# 前端（pnpm workspace，仓库根执行）
pnpm install                             # 安装/更新依赖
pnpm --filter station-platform-web dev   # 平台前端开发（或 cd 进目录后 pnpm run dev）
pnpm --filter station-web dev            # 桌面端内置 Web 开发
pnpm -r typecheck                        # 两端类型检查
pnpm --filter <pkg> build                # 单端构建 + 类型检查

# 发布/冒烟
powershell -File scripts/publish-desktop.ps1
powershell -File scripts/smoke-published-api.ps1

# 安装包（改过 station-web 时先执行 sync 刷新内置前端）
powershell -File scripts/sync-station-web.ps1
powershell -File scripts/package-windows.ps1 -Version 0.1.0      # MSI
bash scripts/package-linux.sh 0.1.0 linux-x64                    # DEB（linux-arm64 同理）
```

## 三、里程碑开发循环（每个 M## 一次）

### 1. 规划

- 确认需求点与验收标准，分配递增的 M 编号（当前最新 M48，新功能从 M49 起）；
- 在 `docs/milestones/` 创建 `M##-xxx.md`，记录目标、方案、验证场景、后续事项。

### 2. Spike 验证（高风险 / 新技术必做）

- 在 `spikes/` 建一次性工程（如 `Station.Spike.MtpSource`）验证关键风险；
- 验证结果以表格记入里程碑文档（场景 / 结果）；
- 结论"通过"后再进入正式实现，避免把风险带进主代码。

### 3. 实现

- **契约先行**：跨端改动先改 `Station.Contracts`，并确认 Desktop / Platform / 前端消费方；
- 分层落地：Domain → Application → Infrastructure → 展示层（见《开发规范》第二章）；
- 安全合规：涉及签名/验签/加密/脱敏/审计的改动按《开发规范》第六章执行；
- 前端新增 API 先补 `api/types.ts`，再写页面。

### 4. 本地验证

- [ ] 两端 Release 构建通过（涉及 Shared 时两端都构建）
- [ ] 涉及前端：`pnpm -r typecheck` + 被改动前端 `pnpm --filter <pkg> build` 通过
- [ ] 涉及共享前端包（`packages/shared`）：两个前端都过 typecheck
- [ ] 涉及 SQL：MySQL + PostgreSQL 验证（有金仓则三库）
- [ ] 涉及桌面端：Windows 至少实际运行一次（模拟源/真机）
- [ ] 涉及平台：`GET /api/v1/health` 正常，核心接口冒烟（可跑 `scripts/smoke-published-api.ps1`）
- [ ] 涉及协议：指令/授权/上报的签名验签联调通过

### 5. 提交

- 按《Git 与协作规范》写提交信息：`type(scope): M## 简述（补充）`；
- 提交前 `git status` / `git diff --check` 自查，确认无敏感文件与构建产物。

### 6. CI

- 推送后确认对应 workflow（`desktop.yml` / `platform.yml`）全绿；
- 共享层改动触发两个 workflow，都需通过。

### 7. 收尾

- 里程碑文档标记 ✅ 通过 + 日期；
- 涉及交付物（部署、发布、运维）时同步更新《部署与运维手册》与 README；
- 如发布，按《CI 与发布规范》执行并打标签。

## 四、跨端协作要点

- **Shared 契约变更 = 全仓影响**：Desktop 与 Platform 必须一起构建验证；
- **Platform 永不引用 Desktop**：需要共享的模型/逻辑放 Shared；
- 数据范围 / RBAC / 脱敏在服务端统一实施，前端只负责展示；
- 平台版运行期间采集站本地数据只读，配置修改须到平台；切回单机版注意"继续用本地数据"与"清空恢复"的差异；
- 协议级修改（指令、上报、签名）必须 Spike 先行 + 两端回归联调。

## 五、日常与交付检查清单

### 每次提交前

- [ ] `git status` / `git diff` 无无关文件
- [ ] 无密钥、`.env`、构建产物、本地库文件
- [ ] 提交信息符合规范（type(scope): M## ...）

### 每天收工

- [ ] 未提交的改动已入库或记录了 TODO
- [ ] 里程碑文档与代码同步

### 每次交付

- [ ] 按《部署与运维手册》交付自检清单逐项勾选
- [ ] 桌面端版本号（`src/Station.Desktop/Directory.Build.props`）与 `desktop-vX.Y.Z` 标签一致；
      平台端版本号（`src/Station.Platform/Directory.Build.props`）与 `platform-vX.Y.Z` 标签一致
- [ ] 打标签发布后核对 GitHub Release 附件：桌面端 MSI + linux-x64/arm64 DEB；平台端 tar.gz
- [ ] 平台默认密码已改、签名/验签密钥已配置

### 日常运维（客户现场）

- 平台日志：`docker compose ... logs -f api`；健康检查：`GET /api/v1/health`；
- 备份：本地库每日 7 份自动；平台每日 30 份 / 手动，按《部署与运维手册》第十章执行；
- 报警中心：磁盘不足、网络中断、USB 故障、校验失败、授权到期等需在界面处置并留审计；
- 记录仪台账：跟踪未绑定 / 非白名单 / 长期未使用预警（默认 30 天）。

## 六、常见错误速查

| 现象 | 处理 |
| :--- | :--- |
| 构建慢 / 不稳定 | 先 `dotnet restore` 再 `dotnet build ... --no-restore` |
| 前端白屏 | 确认发布产物包含 `wwwroot`，访问 `/` 应返回 Vue 入口 |
| 金仓连接失败 | 确认 `DbType=Kdbndp` 兼容串、驱动版本与金仓版本配套 |
| 平台登录后 1 分钟自动退出 | 桌面端空闲登出策略（`Station:Auth:AutoLogoutMinutes`），可配置为 0 关闭 |
| SFTP 上传 Permission denied | 确认 `SftpRoot` 指向可写目录，端口/账号核对 |
| 远端文件大小不一致 | 旧版尾块丢失已修复（显式 Flush），升级后重新上传即可 |
