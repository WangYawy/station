## 一、一页纸看懂安全能力

### 1.1 系统保护了什么

| 保护对象          | 保护方式           | 效果                     |
| :---------------- | :----------------- | :----------------------- |
| **用户登录密码**  | 单向哈希（不可逆） | 数据库泄露也看不到原密码 |
| **授权文件**      | 数字签名           | 无法伪造、无法篡改       |
| **FTP/SFTP 密码** | 对称加密           | 数据库泄露也看不到明文   |
| **采集文件内容**  | 分块加密（可选）   | 磁盘被拆走也读不到文件   |
| **文件完整性**    | 摘要指纹           | 任何改动都能被发现       |
| **文件来源**      | 数字签名           | 证明"文件由哪个站点产生" |
| **记录仪绑定**    | 消息认证码         | 绑定文件无法被伪造       |
| **上报数据**      | 数字签名           | 平台能验证数据来源       |

### 1.2 三种"锁"的比喻

| 比喻             | 技术     | 用来干什么                 |
| :--------------- | :------- | :------------------------- |
| 🔒 **上锁的箱子** | 对称加密 | 保护隐私内容（密码、文件） |
| 🖋️ **防伪印章**   | 数字签名 | 证明来源 + 防篡改          |
| 👆 **指纹**       | 摘要哈希 | 检测改动 + 唯一标识        |

### 1.3 谁能操作什么

| 角色             | 能做什么                           |
| :--------------- | :--------------------------------- |
| **普通用户**     | 无感知使用（登录、采集）           |
| **管理员**       | 设置页切换算法、轮换密钥、查看审计 |
| **运维工程师**   | 部署密钥文件、备份恢复、故障处理   |
| **内部授权工具** | 生成授权文件（持有私钥）           |

### 1.4 三大核心优势

1. **可配置**：算法由管理员选，国密/非国密自由切换
2. **不锁死**：换算法不需改程序、不需停机，用户无感知
3. **可追溯**：所有安全操作留审计，能查谁在什么时候改了什么

### 1.5 与上一版的区别

| 项           | v1.0         | v2.0                                         |
| :----------- | :----------- | :------------------------------------------- |
| **授权文件** | 加密 + 签名  | **只签名不加密**（内容非机密，签名足够防伪） |
| **文件解密** | 先落临时文件 | **流式解密**（大文件不占双倍磁盘）           |
| **加密速度** | 单线程       | **并行分块**（SM4 吞吐提升 3-5 倍）          |
| **集群支持** | 无           | **预留架构**（未来平台统一下发主密钥）       |
| **跨平台**   | Windows 优先 | **Windows / Linux 完全一致**                 |

## 二、加密模式与策略

### 2.1 什么是"加密策略"

**一句话**：加密策略是"**什么场景用什么算法**"的配置清单。

```
策略表（可配置）：
  ┌────────────────────┬─────────────────────┐
  │ 用途（做什么）       │ 算法（用什么）       │
  ├────────────────────┼─────────────────────┤
  │ 用户密码            │ PBKDF2-HMAC-SM3     │
  │ 授权文件            │ SM2-SM3（签名）     │
  │ 文件摘要            │ SM3                 │
  │ FTP 密码            │ SM4-GCM             │
  │ 文件内容加密        │ SM4-GCM（分块）     │
  │ 记录仪绑定          │ HMAC-SM3            │
  │ 平台上报            │ SM2-SM3             │
  └────────────────────┴─────────────────────┘
```

### 2.2 七种用途一览

| 用途             | 说明             | 默认算法        | 是否国密 |
| :--------------- | :--------------- | :-------------- | :------- |
| **登录密码**     | 用户口令存储     | PBKDF2-HMAC-SM3 | ✅        |
| **授权文件**     | 授权防伪（签名） | SM2-SM3         | ✅        |
| **文件摘要**     | 文件完整性指纹   | SM3             | ✅        |
| **敏感字段**     | FTP/SFTP 密码    | SM4-GCM         | ✅        |
| **文件内容加密** | 采集文件落地加密 | SM4-GCM（分块） | ✅        |
| **记录仪绑定**   | 绑定文件防伪     | HMAC-SM3        | ✅        |
| **平台上报**     | 上报数据签名     | SM2-SM3         | ✅        |

**默认全为国密**，如客户要求非国密，可在设置页切换。

### 2.3 国密 vs 非国密对照

| 场景     | 国密（默认）    | 非国密（备选） |
| :------- | :-------------- | :------------- |
| 密码哈希 | PBKDF2-HMAC-SM3 | PBKDF2-SHA256  |
| 对称加密 | SM4-GCM         | AES-256-GCM    |
| 数字签名 | SM2-SM3         | RSA-SHA256     |
| 摘要     | SM3             | SHA-256        |
| 消息认证 | HMAC-SM3        | HMAC-SHA256    |

**切换方式**：设置页 → `🔒 安全与加密` → 选择算法 → 保存

### 2.4 何时可以切换算法

| 用途       | 切换影响             | 旧数据                 |
| :--------- | :------------------- | :--------------------- |
| 登录密码   | 用户下次登录自动升级 | ✅ 可平滑迁移           |
| 敏感字段   | 新写入用新算法       | ✅ 旧密文保留           |
| 文件摘要   | 新文件用新算法       | ✅ 旧文件保留原算法标记 |
| 文件加密   | 新文件用新算法       | ✅ 旧文件保留           |
| 授权文件   | **旧授权需重新生成** | ⚠️ 需通知客户           |
| 记录仪绑定 | **旧绑定文件失效**   | ⚠️ 需重新绑定           |
| 平台上报   | 需平台同步切换       | ⚠️ 需协调               |

**结论**：前四种可随时切换；后三种需协调，一般保持默认。

### 2.5 谁能改策略

| 部署形态   | 谁能改             | 本地是否可改 |
| :--------- | :----------------- | :----------- |
| **单机版** | 本地管理员         | ✅            |
| **平台版** | 平台管理员统一下发 | ❌ 本地只读   |

## 三、密钥生命周期

系统有**两类密钥**，各自不同的管理方式。

### 3.1 两类密钥概览

| 类型         | 用途                                 | 是否离开本机                                   | 谁管理                 |
| :----------- | :----------------------------------- | :--------------------------------------------- | :--------------------- |
| **主密钥**   | 加密数据库敏感字段、派生文件加密密钥 | ❌ 绝不外传（单机）<br>✅ 平台下发（集群，预留） | 系统自动生成，运维备份 |
| **业务密钥** | 授权签名、上报签名                   | ✅ 公钥可分发                                   | 内部工具生成，运维部署 |

### 3.2 主密钥生命周期

```
生成 ────▶ 使用 ────▶ 备份 ────▶ 轮换 ────▶ 保留旧版
 │          │          │          │            │
自动        加解密      运维       管理员       系统自动
(首次启动)  (全程)     (定期)     (主动触发)   (用于旧数据解密)
```

#### 阶段 1：生成

- **时机**：应用首次启动
- **位置**：
  - Windows：`%ProgramData%\Station\keys\master.key`
  - Linux：`/etc/station/keys/master.key`
- **动作**：系统自动生成 32 字节随机密钥，无需人工干预
- **权限**：Windows ACL 限当前账户；Linux `chmod 600`

#### 阶段 2：使用

- 主密钥**永不明文出现**在任何界面或日志
- 由系统内部用于：
  - 加密数据库中的敏感字段（FTP 密码等）
  - 派生文件内容加密密钥（HKDF 派生）

#### 阶段 3：备份（⚠️ 运维必做）

- **备份对象**：`master.key` 文件
- **备份频率**：与数据库备份同步（建议每日）
- **备份方式**：加密压缩包 + 离线存储
- **⚠️ 警告**：**主密钥丢失 = 所有加密数据永久无法解密**

#### 阶段 4：轮换

- **何时轮换**：每年一次 / 安全事件后 / 人员变动后
- **操作**：设置页 → `轮换主密钥` → 确认
- **耗时**：几十秒到几分钟（取决于数据量）
- **是否停机**：不需要，业务无感知

#### 阶段 5：保留旧版本

- 轮换后**不删除旧密钥**（用于解密历史数据）
- 系统自动按密文版本号选择密钥

### 3.3 业务密钥生命周期

#### 授权文件密钥（SM2 密钥对）

```
内部工具生成密钥对
    │
    ├──▶ 私钥 ──▶ 内部工具持有（生成授权用）
    │
    └──▶ 公钥 ──▶ 部署到采集站（验证授权用）
```

| 项       | 说明                                           |
| :------- | :--------------------------------------------- |
| 生成     | 内部授权工具生成，一次性                       |
| 私钥存放 | 内部工具机器，**绝不外传**                     |
| 公钥分发 | 部署到所有采集站 `keys/license-public.pem`     |
| 轮换     | 一般不轮换；如泄露需重新生成并重新授权所有站点 |

#### 上报签名密钥（SM2 密钥对）

| 项       | 说明                                |
| :------- | :---------------------------------- |
| 生成     | 内部工具生成，一次性                |
| 私钥位置 | 采集站 `keys/reporting-private.pem` |
| 公钥位置 | 平台侧（验证上报）                  |
| 轮换     | 一般不轮换                          |

### 3.4 集群模式（预留）

**当前**：单机版（主密钥存本地文件）。

**未来**（管理平台统一管控时启用）：

```
┌──────────────────────────┐
│ 管理平台                  │
│  ├─ 生成客户 KEK          │
│  ├─ 用客户节点公钥包裹    │
│  └─ 下发到所有采集站      │
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│ 采集站                    │
│  ├─ 收到包裹的 KEK        │
│  ├─ 用节点私钥解出 KEK    │
│  ├─ 加密缓存到本地        │
│  └─ 离线也能工作          │
└──────────────────────────┘
```

**收益**：

- 主密钥不出管理平台（只出包裹后的密文）
- 客户隔离（不同客户 KEK 不同）
- 集群共享（同客户所有节点拿到同一份 KEK）
- 离线可用（本地有缓存）

**当前状态**：架构已预留，功能待实现。

### 3.5 密钥部署清单（运维必读）

| 文件                    | 位置            | 来源         | 权限     |
| :---------------------- | :-------------- | :----------- | :------- |
| `master.key`            | 系统密钥目录    | 系统自动生成 | 严格保密 |
| `license-public.pem`    | `keys/`         | 内部工具提供 | 可读     |
| `reporting-private.pem` | `keys/`         | 内部工具提供 | 严格保密 |
| `reporting-public.pem`  | `keys/`（备用） | 内部工具提供 | 可读     |

## 四、业务流程全景

### 4.1 用户登录

```
用户输入密码
    │
    ▼
系统读取密码策略（默认 PBKDF2-HMAC-SM3）
    │
    ▼
用当前算法校验
    │
    ├── 通过 ──▶ 检查是否需要升级算法
    │              │
    │              ├── 是 ──▶ 立即用新算法重哈希 ──▶ 登录成功
    │              │
    │              └── 否 ──▶ 登录成功
    │
    └── 失败 ──▶ 尝试旧算法（迁移期）
                   │
                   ├── 通过 ──▶ 立即用新算法重哈希 ──▶ 登录成功
                   │
                   └── 全失败 ──▶ 记录失败次数
                                  │
                                  └── 达阈值 ──▶ 账号锁定
```

**用户视角**：无感知。**管理员视角**：无需手动干预，用户登录自动迁移。

### 4.2 采集流程

```
插入记录仪
    │
    ▼
识别绑定文件
    │
    ├── 无绑定文件 ──▶ 拒绝接入 ──▶ 提示管理员绑定
    │
    ├── 旧格式 ──▶ 提示重新绑定
    │
    ├── 篡改/无效 ──▶ 拒绝接入 ──▶ 报警
    │
    └── 有效 ──▶ 校验台账（记录仪/用户/部门）
                  │
                  ├── 全部有效 ──▶ 允许采集
                  │
                  └── 部分失效 ──▶ 拒绝 + 提示原因
```

**采集时**：

1. 文件从记录仪复制到本地缓存
2. 计算文件摘要（SM3）
3. 对元数据包签名（SM2）
4. 加密本地缓存文件（SM4-GCM 分块，**并行加密**）
5. 写入数据库记录

### 4.3 上传流程

```
上传文件
    │
    ▼
读取"远端内容模式"配置
    │
    ├── 明文模式（默认）
    │   ├── 边解密边上传（流式，不落临时文件）
    │   └── 远端存储明文
    │
    └── 密文模式
        ├── 直接上传密文文件
        └── 远端存储密文
    │
    ▼
远端校验
    ├── 明文模式：校验大小 + 摘要
    └── 密文模式：仅校验大小
    │
    ▼
上传成功 ──▶ 写入"已上传文件台账"
```

**⚠️ 关键提示**：

- **明文模式**（默认）：平台可直接读取，推荐使用
- **密文模式**：需要平台侧有对应密钥才能解密，适用于高保密场景
- **v2.0 改进**：明文模式采用流式解密，大文件上传不再占用双倍磁盘

### 4.4 授权激活

```
管理员粘贴授权文件
    │
    ▼
系统解析文件结构
    │
    ▼
按文件内算法字段选算法
    │
    ▼
用公钥验证签名
    │
    ├── 无效 ──▶ 拒绝 ──▶ 提示"签名无效"
    │
    └── 有效 ──▶ 解析内容（无需解密）
                  │
                  ▼
              校验业务信息
                  ├── 站点编号 ──▶ 匹配？
                  ├── 硬件指纹 ──▶ 匹配？
                  └── 到期时间 ──▶ 未过期？
                  │
                  ├── 全部通过 ──▶ 激活成功
                  │
                  └── 任一失败 ──▶ 拒绝 + 具体原因
```

**v2.0 说明**：授权文件**只签名不加密**。授权内容本身不是机密，签名足够防伪。

### 4.5 记录仪绑定

```
管理员绑定记录仪
    │
    ▼
写入绑定文件到记录仪根目录
    │
    ▼
生成绑定信息（序列号/用户/部门/时间）
    │
    ▼
从主密钥派生 Binding 密钥（HKDF-SM3）
    │
    ▼
计算 HMAC-SM3 认证码
    │
    ▼
写入 station_bind.ini
```

**防伪原理**：只有持有主密钥的系统才能生成正确 MAC，任何篡改都会导致验证失败。

### 4.6 平台上报

```
采集站产生上报数据（报警/状态）
    │
    ▼
构造规范化 JSON 载荷
    │
    ▼
用私钥签名（SM2-SM3）
    │
    ▼
上报到平台
    │
    ▼
平台用公钥验证签名
    ├── 无效 ──▶ 丢弃 + 告警
    └── 有效 ──▶ 接受数据
```

## 五、版本管理

### 5.1 三种版本号

| 版本类型     | 位置                   | 作用                     |
| :----------- | :--------------------- | :----------------------- |
| **密钥版本** | 密文头部 `v1:` / `v2:` | 支持轮换后读旧数据       |
| **算法版本** | 策略表 + 数据字段      | 支持算法切换后识别旧数据 |
| **协议版本** | STFE 文件头            | 支持文件格式演进         |

### 5.2 密钥版本

**密文格式**：`v1:base64(...)` 或 `v2:base64(...)`

- **写入**：始终用最新版本密钥
- **读取**：按密文头部版本号自动选择密钥
- **效果**：轮换后旧数据仍可读

**用户视角**：

- 无需关心版本
- 轮换后旧文件、旧配置、旧密码全部照常工作

### 5.3 算法版本

**每个数据自带算法标识**：

| 数据     | 算法记录位置                    |
| :------- | :------------------------------ |
| 密码哈希 | 字符串前缀（`sm3$...`）         |
| 密文     | 头部（`v1:...`）                |
| 文件摘要 | 数据库字段 `DigestAlgorithm`    |
| 文件签名 | 数据库字段 `SignatureAlgorithm` |
| 授权文件 | JSON 字段 `signatureAlgorithm`  |

**作用**：切换算法后，系统能识别"这条数据是用旧算法生成的"，按旧算法校验。

### 5.4 协议版本

**STFE 文件格式**：

```
┌──────────────────────────────────────┐
│ Magic "STFE"    ← 文件标识            │
│ Version         ← 格式版本（当前 1）   │
│ Algorithm       ← 加密算法标识        │
│ Key Version     ← 主密钥版本           │
│ Chunk Size      ← 分块大小             │
│ Nonce Seed      ← 随机种子             │
└──────────────────────────────────────┘
```

**演进策略**：新版本格式可平滑读取旧版本，旧版本程序读新格式会明确报错。

### 5.5 版本兼容矩阵

| 场景     | 老数据 + 新程序 | 新数据 + 老程序    |
| :------- | :-------------- | :----------------- |
| 密码     | ✅ 自动迁移      | ❌ 无法识别（报错） |
| 敏感字段 | ✅ 自动识别      | ❌ 无法解密         |
| 文件内容 | ✅ 自动识别      | ❌ 无法解密         |
| 授权文件 | ✅ 自动识别      | ❌ 验签失败         |
| 绑定文件 | ⚠️ 提示重新绑定  | ❌ 验证失败         |

**结论**：升级安全、降级不安全，**务必在升级前备份**。

- □ 审查安全策略是否需要调整
- □ 更新部署文档

### 8.5 关键运维操作 SOP

#### SOP-01：主密钥轮换

**前置条件**：管理员登录 + 有设置权限

**步骤**：

1. 进入设置页 → `🔒 安全与加密`
2. 点击 `轮换主密钥`
3. 确认操作（弹窗二次确认）
4. 等待进度条完成
5. 查看审计列表确认 `MasterKeyRotate` 记录
6. 检查 `FailedCount` 是否为 0

**耗时**：几十秒到几分钟

**回滚**：如失败，查看审计 `Detail` 字段的失败原因

#### SOP-02：备份主密钥

**步骤**：

1. 定位 `master.key` 文件
2. 用加密工具打包（如 7z + 密码）
3. 存到离线介质（移动硬盘、异地备份）
4. 记录备份日期和版本

**⚠️ 警告**：不要明文复制，不要放在公开云盘

#### SOP-03：恢复主密钥

**步骤**：

1. 停止采集站服务
2. 恢复 `master.key` 到原位置
3. 检查权限
4. 启动服务
5. 验证：设置页读取加密字段，确认能正常解密

#### SOP-04：算法切换

**场景**：客户要求从国密改为非国密（或反之）

**步骤**：

1. 确认客户需求和合规要求
2. 通知相关方（密码、授权、上报算法切换有影响）
3. 设置页 → 选择新算法 → 保存
4. 观察 1-2 周
5. 如无问题，可考虑关闭 `允许旧算法回退`

**⚠️ 注意**：

- 密码/敏感字段/文件摘要：可平滑切换
- 授权文件：旧授权需重新生成
- 上报签名：需协调平台同步切换

## 九、故障排查速查表

### 9.1 症状 → 原因 → 处理

| 症状                     | 可能原因                                                | 处理                                                         |
| :----------------------- | :------------------------------------------------------ | :----------------------------------------------------------- |
| **登录一直提示密码错误** | 1. 密码策略被改<br>2. 旧算法不在迁移列表                | 1. 检查策略表 password 行<br>2. 确认 LegacyAlgorithms 含旧算法 |
| **FTP 密码读不出来**     | 1. 主密钥丢失<br>2. 字段 AAD 被改                       | 1. 恢复 master.key 备份<br>2. 检查代码版本是否变更           |
| **授权激活失败**         | 1. 公钥文件错<br>2. 授权文件被篡改<br>3. 硬件指纹不匹配 | 1. 重新部署 license-public.pem<br>2. 重新生成授权<br>3. 换硬件需重新授权 |
| **绑定文件验证失败**     | 1. 旧格式未迁移<br>2. 主密钥被换过                      | 提示用户重新绑定记录仪                                       |
| **主密钥轮换失败**       | 1. 磁盘空间不足<br>2. 权限问题                          | 1. 清理磁盘<br>2. 检查文件写权限                             |
| **启动自检不通过**       | 多种                                                    | 按 `SelfCheckDialog` 提示逐项处理                            |
| **上传文件失败**         | 1. 存储目标配置错<br>2. 熔断打开                        | 1. 自检存储目标<br>2. 等待熔断冷却                           |
| **大文件上传很慢**       | 磁盘 IO 瓶颈                                            | v2.0 已改为流式解密，若仍慢请检查磁盘                        |

### 9.2 常见警告（非错误）

| 警告                               | 含义                       | 是否需处理                   |
| :--------------------------------- | :------------------------- | :--------------------------- |
| `敏感字段存储的是历史明文`         | 数据是旧版本未加密         | 下次保存时自动加密，无需处理 |
| `密码校验命中 legacy 算法`         | 用户在旧算法下登录         | 系统会自动重哈希，无需处理   |
| `熔断打开，跳过上传`               | 存储目标连续失败           | 检查存储服务，等待冷却       |
| `RemoteMasterKeyProvider 尚未实现` | 配置了集群模式但功能未启用 | 将配置改回 `Local`           |

### 9.3 紧急处理

#### 场景 1：主密钥文件损坏

**症状**：启动自检"主密钥加解密"项失败

**紧急处理**：

1. **立即停止所有业务操作**
2. 从备份恢复 `master.key`
3. 如果无备份：联系开发团队，评估数据损失

#### 场景 2：疑似密钥泄露

**紧急处理**：

1. **立即轮换主密钥**
2. 更换所有 FTP/SFTP 密码
3. 重新生成授权文件（如怀疑授权私钥泄露）
4. 通知所有相关方

#### 场景 3：审计日志发现异常操作

**紧急处理**：

1. 记录审计详情（时间、操作人、IP）
2. 检查操作是否经过授权
3. 必要时禁用相关账号
4. 上报安全团队

## 十、常见问题 FAQ

### 10.1 功能类

**Q1：我能不能自己选算法？**
A：可以。设置页 → `🔒 安全与加密`，管理员登录后可选。默认全为国密。

**Q2：切换算法会不会丢数据？**
A：密码、敏感字段、文件摘要类**不会**（自动兼容旧数据）。授权文件、绑定文件切换会影响旧文件。

**Q3：为什么客户看到的 FTP 密码是明文？**
A：这是 UI 展示需要（客户要能查看和修改）。数据库里存的是密文，只有系统运行时才解密。

**Q4：主密钥和授权密钥有什么区别？**
A：

- 主密钥：机器自己用，保护数据库敏感字段、派生文件加密密钥
- 授权密钥：用于验证授权文件，公钥给客户

**Q5：能不能只用国密？**
A：默认就是全用国密，无需额外配置。

**Q6：授权文件到底是加密还是签名？**
A：**只签名，不加密**。授权内容（站点编号、指纹、到期时间）本身不是机密，签名足以防伪。这样采集站只需公钥即可验证，无需与签发方共享主密钥。

### 10.2 操作类

**Q7：主密钥轮换后旧数据还能读吗？**
A：能。系统自动识别数据版本，用对应密钥解密。

**Q8：主密钥文件放在哪里？**
A：

- Windows：`%ProgramData%\Station\keys\master.key`
- Linux：`/etc/station/keys/master.key`

**Q9：能不能把主密钥放到环境变量？**
A：可以。设置 `STATION_MASTER_KEY` 环境变量（base64 编码）。

**Q10：算法改错了怎么回滚？**
A：设置页重新选回原算法。旧数据未受影响（有版本标识）。

**Q11：文件加密占多少磁盘空间？**
A：约增加 0.4%（每 4MB 块加 28 字节头部）。

**Q12：集群部署怎么做？**
A：v2.0 已预留架构（管理平台统一管控主密钥），功能待后续版本实现。当前推荐单机部署。

### 10.3 安全类

**Q13：数据库被窃取，密码会泄露吗？**
A：不会。密码是单向哈希（PBKDF2-HMAC-SM3），无法反推。

**Q14：磁盘被拆走，文件会泄露吗？**
A：如果启用文件加密（默认开启），文件是密文，无主密钥无法读取。

**Q15：如何确认数据没被篡改？**
A：文件有 SM3 摘要，签名文件有 SM2 签名，都能检测篡改。

**Q16：审计日志能删除吗？**
A：不建议。审计用于追溯，删除会破坏合规性。

**Q17：密钥丢了怎么办？**
A：立即从备份恢复。**无备份 = 数据永久丢失**，这是最重要的运维红线。

### 10.4 运维类

**Q18：多久备份一次主密钥？**
A：与数据库备份同步，建议每日。

**Q19：主密钥轮换需要停机吗？**
A：不需要。轮换过程业务无感知。

**Q20：怎么知道有没有被攻击过？**
A：查审计日志。异常登录、异常算法变更都会记录。

**Q21：平台版和单机版安全策略一样吗？**
A：技术一样。区别是平台版由平台统一下发策略，本地只读。

**Q22：升级程序会不会影响密钥？**
A：正常升级不会。但**升级前必须备份** `master.key`，以防万一。

**Q23：文件加密速度会不会很慢？**
A：v2.0 采用并行分块加密，SM4 吞吐比单线程提升 3-5 倍。4 核 CPU 可达 ~600 MB/s。

**Q24：上传 GB 级文件会不会占双倍磁盘？**
A：不会。v2.0 改为流式解密，内存占用恒定（约 4MB），不再落临时文件。

## 十一、术语表

| 术语         | 通俗解释                                    |
| :----------- | :------------------------------------------ |
| **主密钥**   | 系统内部的大钥匙，用来保护所有敏感数据      |
| **业务密钥** | 用于授权、签名的密钥对（公钥 + 私钥）       |
| **国密算法** | 中国国家密码管理局发布的算法（SM2/SM3/SM4） |
| **SM2**      | 国密椭圆曲线签名算法（类似 RSA）            |
| **SM3**      | 国密摘要算法（类似 SHA-256）                |
| **SM4**      | 国密对称加密算法（类似 AES）                |
| **HMAC**     | 带密钥的摘要，用于防伪                      |
| **HKDF**     | 从主密钥派生其他密钥的算法                  |
| **AAD**      | 附加认证数据，绑定密文与上下文              |
| **STFE**     | 本系统文件加密格式（分块 SM4-GCM）          |
| **策略表**   | 存放"什么场景用什么算法"的数据库表          |
| **审计日志** | 记录所有关键操作的日志表                    |
| **版本化**   | 数据带版本号，支持算法/密钥演进             |
| **惰性迁移** | 用户使用时自然迁移，无需批量操作            |
| **熔断**     | 存储目标连续失败时暂停上传的机制            |
| **流式解密** | 逐块解密，不落临时文件，内存恒定            |
| **并行分块** | 多块同时加密，充分利用多核 CPU              |
