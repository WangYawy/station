## 三、逐领域详细选型与理由

### 3.1 采集站桌面端 — 核心框架

**选型结论**：.NET 8 + Avalonia UI 12.x + CommunityToolkit.Mvvm 8.4.x

**理由**：

- **.NET 8 LTS** 是微软官方长期支持版本（支持至 2026 年 11 月），官方支持 Windows、Linux 的 x64 与 ARM64 运行时，满足信创目标架构（海光/兆芯 x86_64、飞腾/鲲鹏 ARM64）。龙芯 LoongArch 不在 .NET 8 官方支持范围，按需求放 P2。
- **Avalonia UI 12.x** 是目前唯一成熟的 .NET 跨平台桌面 UI 框架，XAML + 代码后置的开发模式与 WPF 一致；自绘渲染引擎不依赖操作系统原生控件，确保 Windows/Linux/麒麟/统信多端 UI 表现一致。ARM64 下需提前验证渲染依赖（Skia/HarfBuzz 原生库）。
- **CommunityToolkit.Mvvm 8.4.x** 通过源生成器自动生成 `INotifyPropertyChanged` 和 `ICommand`，可减少约 40% 的样板代码。

**UI 设计稿对应**：三套 UI 设计（桌面端、单机版 Web 后台、管理平台 Web 后台）均采用**执法蓝白风格**（主色 `#0a2f6c` 深蓝 + `#2563eb` 亮蓝 + 白色背景）。Avalonia UI 通过 `Styles` 和 `ResourceDictionary` 完整实现该设计语言。

------

### 3.2 采集站桌面端 — 数据持久化

**选型结论**：SqlSugar 5.1.x + SQLite（Microsoft.Data.Sqlite）8.0.x，同时 P0 支持 Kingbase（Kdbndp 驱动）

**理由**：

- **SqlSugar** 支持 SQLite、MySQL、PostgreSQL、Kingbase 等多数据库，CodeFirst 自动建表、批量插入、内置分页等能力匹配 MVP 的 CRUD 密集特征；同一套 ORM 服务采集站与平台，数据访问层可替换。
- **SQLite** 采用 `Microsoft.Data.Sqlite` 官方驱动，零配置、单文件存储，安装包增量 <500KB；采用 **WAL 模式**缓解 30 路并发写入锁争用。
- **Kingbase（人大金仓）** 为信创硬性要求：通过官方驱动 **Kdbndp** 接入，SqlSugar 以 `DbType.Kingbase` 适配；建表、迁移、分页、事务、索引与 SQLite 存在差异，需在数据访问层统一封装并做专项联调。
- **平台侧三库差异**（MySQL/PostgreSQL/Kingbase）：分页语法（LIMIT/OFFSET 兼容）、事务隔离级别、字段大小写、JSON 类型、自增/序列等差异由 SqlSugar 抽象层收敛；数据库脚本按三库分别维护。

**实体设计**（MVP 核心实体）：

- 部门、账号、用户（人员）、角色、角色权限点、记录仪（含白名单）、采集站、采集任务、视音频文件、上传任务、报警记录、授权记录（License）、审计日志、设备日志、待上报队列字段（业务表上报状态）、同步版本记录、备份记录（共 17 类核心实体/表）。

------

### 3.3 采集站桌面端 — 设备对接与记录仪身份识别（关键差异点）

**选型结论**：抽象设备驱动层 + 平台特定实现 + 自研 ini 身份识别

**理由**：

这是采集站**最核心的技术难点**，需要同时支持 USB Mass Storage、MTP、私有加密（SDK 转 UMS 模式）三种接入方式，且跨 Windows/Linux/麒麟/统信、x86_64 + ARM64。

| 协议                 | Windows 实现                              | Linux/Kylin/UOS 实现                    | 说明                          |
| :------------------- | :----------------------------------------- | :--------------------------------------- | :---------------------------- |
| **USB Mass Storage** | 系统自动挂载为盘符，`System.IO` 直接访问   | 系统自动挂载（`/media/`），`System.IO` 直接访问 | 最简单，跨平台一致            |
| **MTP**              | Windows Portable Devices (WPD) COM Interop | libmtp P/Invoke                          | 需抽象 `IMtpDeviceService` 接口 |
| **私有加密**         | 厂商 SDK 将设备转为 UMS 模式               | 取决于厂商 SDK 是否提供 Linux 版本        | 转 UMS 后按文件系统直读处理    |

**记录仪身份识别（ini 绑定）**：

- 绑定写入：台账管理（单机版 Web / 平台）在设备已连接时执行"写入绑定"，将记录仪编号、用户、部门、绑定时间 + SM3 校验值写入设备根目录 ini。
- 接入识别（三层）：无 ini = 未绑定；ini SM3 校验失败 = 疑似篡改；编号不在台账/白名单 = 非授权接入。
- 绑定不一致（编号存在、绑定变化）：以台账为准，接入时自动重写 ini。
- 未绑定设备默认**禁止采集**（界面提示 + 报警）；"允许采集标待归属"为可配置项。
- 实现要点：`IdentityService` 负责 ini 读写与校验；`IDevicePlugin` 抽象设备枚举；平台差异封装在 Infrastructure 层。

**热插拔监听**：

- **Windows**：`System.Management.ManagementEventWatcher` 监听 `Win32_DeviceChangeEvent`
- **Linux/Kylin/UOS**：通过 `Socket` 连接 udev netlink，监听 `add`/`remove` 事件

### 3.4 采集站桌面端 — 网络通信与国密

**选型结论**：IHttpClientFactory + Polly + BouncyCastle.Cryptography + 三套独立轮询

**理由**：

- **P0 通信基线**：HTTPS API + 独立轮询，三套间隔独立配置：心跳/状态上报 30 秒、远程指令拉取 10 秒、配置同步增量 60 秒（启动时全量拉取一次）。`IHttpClientFactory` 配合 Polly 实现超时与指数退避重试。
- **元数据上报**：文件采集完成入库后即时上报一条；失败写入业务表上报状态字段（上报状态、失败次数、下次重试时间），网络恢复事件 + 心跳周期兜底扫描补报。
- **WebSocket/SignalR**：作为 **P1**，用于实时状态推送与平台配置变更主动通知；P0 不依赖长连接。
- **国密算法支持**：文件 SM3 哈希校验、元数据 SM2 数字签名、本地文件 SM4 加密存储。`BouncyCastle.Cryptography` 是 .NET 生态中最成熟的国密算法库，支持 SM2/SM3/SM4 全套算法。

### 3.5 采集站桌面端 — 安全加密与授权

**选型结论**：BouncyCastle.Cryptography（国密）+ BCrypt.Net-Next（密码）+ 自研 LicenseManager（离线授权）

| 安全需求     | 技术方案    | 说明                                                   |
| :----------- | :---------- | :----------------------------------------------------- |
| 文件完整性   | SM3 哈希    | 每个采集文件计算 SM3；上传完成后远端文件 SM3 二次校验（P0） |
| 元数据签名   | SM2 数字签名 | 采集站上报元数据时用私钥签名，平台验签                |
| 本地文件加密 | SM4-CBC     | 采集完成文件先加密存放于本地缓存区                    |
| 存储凭据加密 | SM4         | FTP/SFTP 密码等敏感配置加密存储                       |
| 用户密码     | BCrypt      | 桌面端/单机版 Web/平台账号密码哈希，本地验证          |
| ini 防篡改   | SM3 校验值  | 记录仪绑定 ini 内容校验，篡改按"绑定信息异常"处理      |
| 授权信息     | SM4         | 离线授权文件/注册码加密存储                           |

**授权机制**：

- **P0 仅离线授权**：采集站生成机器指纹（CPU 序列号 + 主板序列号 + 磁盘序列号 + MAC 组合）→ 客户提交厂商 → 厂商内部工具生成注册码/授权文件 → 导入激活；一台一码，换硬件需重新授权。
- 30 天试用（全功能）→ 7 天宽限（全功能 + 醒目提醒）→ 锁定（仅查看/导出）；授权到期瞬间立即中断当前采集；时钟回拨检测自动锁定。
- 授权信息 SM4 加密存储；LicenseManager 自研。

### 3.6 采集站桌面端 — 文件处理、上传与 30 路并发

**选型结论**：System.IO.Pipelines + FluentFTP（断点续传/分片）+ Channel 队列

**理由**：

- MVP 要求单路采集速率不低于 20MB/s，架构预留 30 路并发、按实际接口数验收。`System.IO.Pipelines` 实现零拷贝和背压控制，适合大文件分块读写。
- **上传策略**：采集完成文件先存放于本地加密缓存区，再按策略上传至存储目标（本地磁盘/FTP/SFTP）。FTP/SFTP 使用 **FluentFTP** 实现断点续传/分片，断网恢复后接着传，不整文件重传。
- **存储成功判定**：上传完成后对远端文件计算 SM3 与本地比对，一致才算成功；不一致按上传失败处理（重新上传 + 异常报警）。
- **重试与熔断**：重试次数/间隔在采集策略中可配置（默认无限重试、间隔 30 秒）；同一存储目标连续失败 5 次进入简单版熔断（默认 10 分钟），到期自动恢复，熔断期间报警。
- **任务队列**：`System.Threading.Channels` 实现生产者-消费者模式，管理 30 路采集任务与上传任务的并发调度。
- **缓存清理**：按保留天数（默认 30 天）清理已上传的本地加密缓存，清理留审计。

### 3.7 单机版内置 Web 服务

**选型结论**：ASP.NET Core 自托管轻量宿主（业务接口 Controller 分层）+ 静态文件托管 + Cookie Authentication + RBAC

**理由**：

- 单机版采集站内置 Web 服务，默认仅本机访问，可配置开启局域网访问；开启后必须 HTTPS、登录认证与访问日志。
- **ASP.NET Core 自托管宿主** 无 IIS 依赖、可嵌入桌面应用；业务接口采用 **Controller 分层**（Auth/User/Dept/Recorder/File/Audit/Setting），每个模块一个 Controller，逻辑下沉到 Application 用例层，避免 lambda 路由散落导致业务界限模糊。
- **HTTPS**：自动生成 SM2 自签名证书，默认启用；同时支持管理员导入正式证书。
- **身份认证**：Cookie Authentication + **RBAC**（单机版与平台版统一 RBAC，预置管理员/部门负责人/操作员/审计员四角色 + 自定义角色权限点）。
- **前端资源**：以 Vue 3 组件化实现并托管于 wwwroot；设计稿仅作视觉参考。

### 3.8 监控管理平台 — 后端

**选型结论**：ASP.NET Core 8 WebAPI + SqlSugar + 三库（MySQL/PostgreSQL/Kingbase）+ Redis（P1 可选）+ 备份服务

**理由**：

- **ASP.NET Core 8 WebAPI**：与采集站共享 .NET 8 技术栈，提供 RESTful API 供前端调用。
- **SqlSugar + 三库**：与采集站共用 ORM；平台数据库 **MySQL/PostgreSQL/Kingbase 三库均为 P0**（信创硬性要求），通过配置切换；三库脚本分别维护，SqlSugar 抽象分页、事务、索引差异。
- **配置同步**：提供组织、用户、记录仪、白名单、采集策略、账号数据的全量/增量同步接口（版本号 + updated_at），采集站启动全量 + 60 秒增量轮询。
- **远程指令**：指令队列 + SM2 签名 + 采集站独立轮询（10 秒）拉取；六类 P0 指令（重启采集服务、清理本地缓存、重新拉取配置、执行自检、停止采集、启动采集）；执行结果回执闭环；超时标记失败、人工重发。
- **文件预览**：P0 采用**采集站代理转发**——平台受控接口 → 采集站在线时从存储目标读取文件流式转发（Range 请求 + 限流），平台不直连存储、不暴露存储路径；H.264 在线播放，H.265 引导下载；P2 采集站侧 FFmpeg 转码。
- **SignalR / Redis**：P1（实时推送、分布式缓存）；P0 不硬依赖 Redis。
- **备份服务**：每日自动备份（调用各库原生工具 mysqldump / pg_dump / kdb_dump）、保留份数可配置、支持手动备份。

### 3.13 视频预览与转码

**选型结论**：P0 采集站代理转发预览（原生 video + Range + 限流）；P2 采集站侧 FFmpeg 转码模块

**理由**：

**选型结论**：平台每日自动备份 + 采集站本地库每日快照

**理由**：

- **平台**：每日定时调用数据库原生备份工具（mysqldump / pg_dump / kdb_dump），保留份数可配置，支持手动备份；备份动作记录审计日志。
- **采集站**：每日定时对本地库做快照（SQLite 文件拷贝 / Kingbase 导出），保留最近 7 份；备份动作留审计。

### 3.15 跨端 ID 与数据同步设计

**选型结论**：三层 ID 规则（本端自增代理键 + 业务编号自然键 + 平台入库自增主键），不使用雪花 ID；同步以业务编号为幂等键

**理由**：

- **本端自增（代理键）**：采集站与平台各自数据库内部使用自增主键，仅用于本端内部关联，不跨端传输。
- **业务编号（自然键）**：采集站编号、记录仪序列号、用户工号、部门编码全局唯一；文件业务编号 = `{采集站编号}-{本地文件ID}`，如 `CS-01-001-00012345`。
- **平台入库**：平台 `FileRecord` 使用自增 `Id` 作主键，建唯一索引 `(StationId, LocalFileId)`：

```text
FileRecord
├── Id                平台自增（统一列表用）
├── StationId         平台 Station 表自增 Id（外键）
├── StationCode       采集站编号（冗余，便于查询）
├── LocalFileId       采集站本地文件 ID（上报字段）
├── FileNo            CS-01-001-00012345（业务编号，展示用）
└── UNIQUE (StationId, LocalFileId)   -- 补报/重试幂等
```

- **幂等规则**：断网补报、重试上报时命中唯一索引，平台执行 upsert（更新状态）或忽略，不产生重复记录；统一列表查询即 `FileRecord` 关联采集站/用户/组织表，按平台 ID 分页展示。
- **注册衔接**：采集站首次连接平台按"采集站编号 + 机器指纹"注册，平台返回 `StationId` 并本地缓存；断网沿用缓存值，恢复后继续上报。
- **契约版本化**：通信契约只增不改不删，破坏性变更走 API 版本化（`/api/v1` → `/api/v2`），允许两端不同步升级。
- **ID 稳定性保障**：采集站本地文件元数据记录不物理删除（软删/保留），本地 ID 永不复用；采集站编号录入后不可变更，避免自然键漂移。

**推荐**：平台三库均通过 SqlSugar 统一接入；采集站本地 Kingbase 使用 Kdbndp。

### 5.3 视频转码（P2）

| 方案       | 版本 | 许可证 | 说明                                            |
| :--------- | :--- | :----- | :---------------------------------------------- |
| **FFmpeg** | 6.x+ | LGPL/GPL | 采集站侧 H.265 → H.264 转码；自包含构建（x86_64 + ARM64） |

**推荐**：P2 在采集站侧集成 FFmpeg 独立转码模块，生成 H.264 预览版本并缓存。

### 5.4 对象存储（OOS/S3）— MVP 延后

MVP 阶段仅支持本地磁盘和 FTP/SFTP，OOS/S3 作为后续迭代。届时可选用 AWS SDK for .NET（S3 兼容）或 MinIO .NET SDK。

### 5.5 NAS 挂载

NAS（NFS/CIFS）在操作系统层面挂载为网络驱动器后，采集站通过普通文件路径访问即可，无需额外 .NET 库。

### 5.6 生物识别 SDK

指纹/人脸登录为 P2。届时需根据采集站硬件配置选用对应 SDK（指纹：中控 ZK 系列、汇顶；人脸：虹软 ArcFace、百度 AI 等）。

## 七、风险与注意事项

| 编号 | 风险                                       | 影响                     | 概率 | 缓解措施                                                     |
| :--- | :----------------------------------------- | :----------------------- | :--- | :----------------------------------------------------------- |
| R-01 | 三库双端适配（MySQL/PostgreSQL/Kingbase + SQLite/Kingbase） | 建表、迁移、分页、事务差异导致返工 | 高   | SqlSugar 抽象 + 三库脚本分库维护；Kingbase 尽早引入联调    |
| R-02 | Linux 下 libmtp 对 Kylin/UOS ARM64 兼容性未验证 | MTP 设备在麒麟 ARM64 不可用 | 高   | 抽象 `IMtpDeviceService`，可降级为仅支持 UMS + 私有 SDK 转 UMS |
| R-03 | 私有加密 SDK 仅提供 Windows DLL，无 Linux 版本 | 私有设备在 Linux 不可用 | 中   | 按平台加载插件，Linux 标记"不支持"并提示               |
| R-04 | ini 绑定安全（UMS 无法验证物理身份，存在复制/篡改） | 归属错误、伪造身份 | 中   | SM3 校验 + 台账一致性比对；疑似篡改按未绑定处理并报警；P1 MTP 序列号交叉验证 |
| R-05 | 30 路并发导致 SQLite 写锁争用               | 日志写入延迟             | 低   | 启用 WAL 模式 + 异步日志批量提交                            |
| R-06 | BouncyCastle 在麒麟/统信兼容性              | 国密算法调用失败         | 低   | 提前在信创环境验证，备选方案使用系统 OpenSSL                |
| R-07 | Avalonia UI 在麒麟 V10 ARM64 的渲染兼容性   | UI 显示异常               | 中   | 使用 Avalonia 12.x 稳定版，提前在 ARM64 环境做 UI 适配测试  |
| R-08 | FTP/SFTP 断点续传/分片在目标存储上的兼容性  | 续传失败、校验不一致     | 中   | 选用 FluentFTP 成熟实现，按目标存储实测（含远端 SM3 二次校验） |
| R-09 | H.265 播放限制                              | 客户误认为不能播放       | 中   | 界面明确"格式不支持，引导下载"；P2 采集站侧转码             |
| R-10 | 单机版内置 Web 自签名证书浏览器警告         | 用户体验受影响           | 低   | 部署手册提供证书导入指导，支持导入正式证书                  |
| R-11 | 平台预览依赖采集站在线                     | 采集站离线时无法预览     | 中   | P0 接受（离线只查元数据）；P2 提供平台直连存储可配置模式     |

所有选型均满足开发基线需求的功能要求、性能指标（30 路并发预留、单路 ≥20MB/s）和非功能要求（跨平台 x86_64 + ARM64、三库双端、国密、HTTPS、日志脱敏、备份恢复、离线授权）。
