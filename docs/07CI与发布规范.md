# 视音频数据采集站与监控管理平台 — CI 与发布规范

> 版本：0.1.0（基线）　配套：《开发规范》《Git 与协作规范》《部署与运维手册》

## 一、CI 现状与触发规则

仓库使用 GitHub Actions（`.github/workflows/`）：

| 工作流 | 触发路径 | 构建内容 |
| :--- | :--- | :--- |
| `desktop.yml` | `src/Station.Shared/**`、`src/Station.Desktop/**`、`station-web/**`、`Station.Desktop.sln`、`Directory.Build.props`、工作流自身 | 桌面端 Release 构建：`windows-latest` + `ubuntu-latest`（.NET 8）；单机版 Web 前端：`station-web`（Node 20） |
| `platform.yml` | `src/Station.Shared/**`、`src/Station.Platform/**`、`station-platform-web/**`、`Station.Platform.sln`、`Directory.Build.props`、工作流自身 | 平台后端 Release 构建：`ubuntu-latest`（.NET 8）；平台前端：`station-platform-web`（Node 20） |
| `release.yml` | 标签 `v*`（push）或 `workflow_dispatch` | 桌面端发布：构建前端 → 三平台 publish → 生成 Windows MSI（WiX v5）+ Linux DEB（x86_64/ARM64，dpkg-deb）→ 上传 GitHub Release |

- 触发方式：`push` 与 `pull_request`，按路径过滤；
- 约定：
  - Action 固定主版本 tag：`actions/checkout@v4`、`actions/setup-dotnet@v4`；
  - 构建顺序固定：`dotnet restore <sln>` → `dotnet build <sln> -c Release --no-restore`；
  - 新增共享层工程或调整目录时，**两个工作流的路径过滤必须同步更新**；
  - 改动 `Station.Shared` 时，桌面端与平台两个 workflow 都会被触发，属预期行为。

## 二、质量门禁（现状与目标）

### 已落地

- 桌面端后端：Windows + Linux 双平台 Release 构建；
- 平台后端：Linux Release 构建。
- 前端质量门禁：`station-web` 并入 `desktop.yml`、`station-platform-web` 并入 `platform.yml`，
  流程为 Node 20 + `npm ci` + `npm run build`（含 `vite build` 与 `vue-tsc --noEmit`）；
  构建产物写入对应 `wwwroot`，仅验证可构建性，工作区产物变更不入库。

### 待补齐（新里程碑逐步实施；提交前本地必须手动执行）

1. **单元/集成测试**：测试项目回归后接入 `dotnet test`；
2. **发布产物冒烟**：平台 API 用 `scripts/smoke-published-api.ps1` 验证（首页 + 登录 + 文件接口）；
3. **代码风格校验**（可选）：`dotnet format --verify-no-changes`、SonarAnalyzer。

### CI 失败处理

- 先读失败日志定位根因，禁止"重跑碰运气"；
- 构建类问题（依赖、路径、SDK 版本）优先在本地复现；
- 工作流配置变更（触发路径、Action 版本、步骤）需评审后合入。

## 三、发布规范

### 桌面端

- 统一使用 `scripts/publish-desktop.ps1` 发布三个目标：

  ```powershell
  powershell -File scripts/publish-desktop.ps1
  # 产物：publish/desktop/win-x64 | linux-x64 | linux-arm64
  ```

- 目标架构映射：海光/兆芯等 x86_64 → `linux-x64`；飞腾/鲲鹏等 ARM64 → `linux-arm64`；
- 参数：单文件、自包含（`PublishSingleFile` + `IncludeNativeLibrariesForSelfExtract`）；
- 发布前自检：对应 sln Release 构建通过、CI 绿、按《部署与运维手册》交付自检清单逐项验收。

#### 安装包（Windows MSI / Linux DEB）

- **Windows**：`scripts/package-windows.ps1`（publish → WiX v5 → `.msi`）

  ```powershell
  powershell -File scripts/package-windows.ps1 -Version 0.1.0
  # 产物：publish/packages/Station.Desktop-0.1.0-win-x64.msi
  ```

  - WiX v5 已弃用 heat.exe，文件收集由 `scripts/wix/Station.Desktop.wxs` 的 `<Files Include=".../**">` 完成；
  - 安装包**不包含** `station.db`（运行期数据）与 `*.pdb`；`appsettings.json` 不进包，应用按默认配置运行，
    部署时按《部署与运维手册》在安装目录新建/修改；
  - 升级走 `MajorUpgrade`（固定 UpgradeCode，覆盖安装）；WiX 固定 5.0.2（v5 为最后免费版本）。

- **Linux/Kylin/UOS**：`scripts/package-linux.sh`（publish → dpkg-deb → `.deb`，分架构构建）

  ```bash
  bash scripts/package-linux.sh 0.1.0 linux-x64
  bash scripts/package-linux.sh 0.1.0 linux-arm64
  # 产物：publish/packages/station-desktop_0.1.0_amd64.deb（arm64 同理）
  ```

  - 早期选型的 dotnet-deb 工具已实测不可用（要求向工程注入废弃的 Packaging.Targets），
    改用系统自带 `dpkg-deb`，产出仍是标准 `.deb`；
  - 包内：`/usr/lib/station-desktop/`（程序 + wwwroot）、`/usr/bin/station-desktop` 软链、桌面快捷方式；
    `appsettings.json` 声明为 conffile，升级不覆盖用户修改；
  - 安装：`sudo dpkg -i station-desktop_0.1.0_amd64.deb`。

- **内置前端同步**：发布/打包前必须把 `station-web` 新构建产物同步进
  `src/Station.Desktop/Station.Desktop.WebHost/wwwroot/`（该目录是入库的构建产物）：

  ```powershell
  powershell -File scripts/sync-station-web.ps1   # npm ci + build + 同步
  ```

  CI 的 `release.yml` 自动执行；本地改过前端再打包时手动执行，并把变更后的资产一并提交。

- **运行数据目录注意**：桌面端把 `station.db` 与采集文件写在**进程工作目录**（连接串为相对路径）。
  Windows 安装到 `Program Files` 后须以可写账户（如管理员）运行；Linux deb 桌面启动时工作目录为用户主目录（可写）。
  如需把数据固定到 `%ProgramData%` / `/var/lib`，属应用改造，后续版本处理。

#### GitHub Release 发布

- 推标签即发布：

  ```bash
  git tag v0.1.0
  git push origin v0.1.0
  ```

- `release.yml`（标签 `v*`）自动执行：构建 `station-web` → 同步 wwwroot → 三平台 publish → 生成
  MSI + 两个 DEB → 经 `softprops/action-gh-release@v2` 上传到对应 tag 的 GitHub Release，产物：

  ```text
  Station.Desktop-0.1.0-win-x64.msi
  station-desktop_0.1.0_amd64.deb
  station-desktop_0.1.0_arm64.deb
  ```

- 权限：工作流顶部 `permissions: contents: write`，私有仓库使用内置 `GITHUB_TOKEN` 即可，无需额外配置；
- `workflow_dispatch` 手动触发只产出制品（Actions 页可下载），不创建 Release；
- **后备方案 Velopack**：若后续需要桌面端自动更新/增量更新，可切换 Velopack
  （Windows `Setup.exe` + `--msi`、Linux AppImage、macOS dmg），其 `vpk upload github` 原生发布 GitHub Release，
  需在应用启动时接入 Velopack 运行时。

### 平台端

- 交付包位于 `deploy/platform/`：`Dockerfile` + 三套 compose（MySQL / PostgreSQL / Kingbase）+ `.env.example`；
- 发布步骤：

  ```bash
  cp deploy/platform/.env.example deploy/platform/.env   # 填入真实密码/密钥/端口
  docker compose -f deploy/platform/docker-compose.yml --env-file deploy/platform/.env up -d --build
  ```

- 生产必配：`PLATFORM_COMMAND_PRIVATE_KEY`（指令签名私钥）、`PLATFORM_REPORTING_PUBLIC_KEY`（上报验签公钥），否则以开发模式运行；
- 平台镜像已内置 wqy-microhei 字体（PDF 导出），裸机部署需自行安装 CJK 字体或配置 `STATION__EXPORT__FONTFILE`；
- 首次启动自动建库建表并播种默认管理员，**生产必须立即改默认密码**。

### 版本与产物

- 版本号：`Directory.Build.props` 的 `<Version>`（当前 `0.1.0`）与前端 `package.json` 保持一致，发布时统一递增；
- 发布打标签 `v0.x.y`；
- 产物目录约定（不入库）：

  ```text
  publish/
  ├── desktop/win-x64/       # 桌面端 Windows 单文件
  ├── desktop/linux-x64/     # 桌面端 信创 x86_64
  ├── desktop/linux-arm64/   # 桌面端 信创 ARM64
  ├── packages/              # 安装包（MSI / DEB），由 release.yml 上传 GitHub Release
  └── platform-api/          # 平台 API 发布产物（冒烟测试用）
  ```

## 四、密钥与 CI 安全

- 所有密钥通过 GitHub Secrets / 部署环境变量注入；工作流中禁止打印、落盘或写进制品；
- 只提交 `.env.example`，真实 `.env` 一律不入库（`.gitignore` 已覆盖）；
- 变更签名/验签相关配置时，必须核对两端公钥/私钥配套，联调通过后才能发布；
- 交付前检查项：默认密码已改、安全密钥已配置、HTTPS 可用。
