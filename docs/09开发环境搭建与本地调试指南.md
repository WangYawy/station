# 开发环境搭建与本地调试指南（新成员入门）

> 适用：新加入的开发者。目标：按本文档一步步把四个开发目标在本地跑起来并调试。
> 配套：《README》《开发规范（docs/05）》《日常开发流程与检查清单（docs/08）》《CI 与发布规范（docs/07）》

## 一、四个开发目标总览

| # | 目标 | 工程 / 目录 | 入口 | 本地地址 | 前置依赖 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 桌面端应用（Avalonia） | `src/Station.Desktop`，`Station.Desktop.sln` | `Station.Desktop.UI`（WinExe） | 窗口程序；自带内置 Web `http://127.0.0.1:5000` | .NET SDK 8；SQLite 自动建库，零配置 |
| 2 | 管理端后端（WebAPI） | `src/Station.Platform`，`Station.Platform.sln` | `Station.Platform.Api`（Exe） | `http://127.0.0.1:5100` | .NET SDK 8 + MySQL / PostgreSQL / 金仓（Docker 一键起） |
| 3 | 单机版内置 Web 前端 | `station-web`（Vue 3 + Vite） | `pnpm --filter station-web dev` | `http://localhost:5174`，`/api` 代理到 `127.0.0.1:5000` | Node 20+ / pnpm 9；**桌面端应用需在运行**（提供接口） |
| 4 | 管理平台 Web 前端 | `station-platform-web`（Vue 3 + Vite） | `pnpm --filter station-platform-web dev` | `http://localhost:5173`，`/api`、`/hubs` 代理到 `127.0.0.1:5100` | Node 20+ / pnpm 9；**平台 API 需在运行** |

关系图：

```text
station-web (5174, 开发服务器) ──/api──▶ 桌面端应用 · 内置 Web (127.0.0.1:5000) ──SQLite──▶ %LOCALAPPDATA%\Station\station.db
station-platform-web (5173, 开发服务器) ──/api、/hubs(ws)──▶ Station.Platform.Api (127.0.0.1:5100) ──MySQL/PG/金仓──▶ station_platform
桌面端应用（可选，Station:Platform:Enabled=true）──上报/指令──▶ Station.Platform.Api
```

前端两工程共用 `packages/shared`（`@station/shared`：请求封装 / 公共类型 / 工具），由根目录 pnpm workspace 统一管理。

## 二、一次性环境准备

### 1. 工具清单

| 工具 | 版本要求 | 用途 | 获取 |
| :--- | :--- | :--- | :--- |
| Git | 任意较新版本 | 拉取仓库 | https://git-scm.com |
| .NET SDK | **8.0.x**（与 CI 一致） | 两端后端编译运行 | https://dotnet.microsoft.com/download |
| Node.js | 20+（满足 Vite 6 要求） | 前端工程 | https://nodejs.org |
| pnpm | 9.x（与根 `package.json` 的 `packageManager` 一致） | 前端包管理 | `npm install -g pnpm` 或 `corepack enable` |
| IDE | 任选其一 | 开发调试 | 见下 |

- **C# 调试推荐**：Visual Studio 2022（Windows）或 JetBrains Rider（Windows / Linux），直接打开 `.sln` 即可 F5；
- **前端编辑推荐**：VS Code + Vue 官方扩展（Volar）+ ESLint；C# 侧也可用 VS Code + C# Dev Kit（功能弱于 VS/Rider，仅命令行开发可不用 IDE）；
- **数据库（可选）**：Docker Desktop / Docker Engine，用于一键起 MySQL / PostgreSQL（见第三章）。

### 2. 验证安装

```powershell
git --version
dotnet --version        # 期望 8.0.x
node -v                 # 期望 ≥ 20
pnpm -v                 # 期望 9.x
```

### 3. 拉取仓库

```powershell
git clone <仓库地址> station
cd station
git checkout main
```

仓库目录结构见 `README.md`（`src/` 为 .NET 端，`station-web` / `station-platform-web` 为前端，`packages/shared` 为前端共享包）。

### 4. 安装前端依赖（一次性，仓库根执行）

```powershell
pnpm install
```

会同时安装 `station-web`、`station-platform-web`、`packages/shared` 三个 workspace 成员的依赖，并生成根目录 `pnpm-lock.yaml`。以后任何人改了依赖（`package.json`）都要回到根目录重新执行 `pnpm install`。

### 5. 首次构建自检

```powershell
# 后端（无前端参与，纯 .NET 编译）
dotnet build .\Station.Desktop.sln -c Release
dotnet build .\Station.Platform.sln -c Release

# 前端类型检查（两端一起）
pnpm -r typecheck
```

全部通过说明环境就绪。若 `dotnet restore` 拉包慢或失败，见第八章"常见问题"。

## 三、数据库准备

### 桌面端（零配置）

桌面端使用 **SQLite**，首次启动自动建库：数据文件在系统数据目录
`%LOCALAPPDATA%\Station\station.db`（Windows）/ `~/.local/share/Station/station.db`（Linux），
可用环境变量 `STATION__DATA__DIR` 覆盖。开发中想重置数据，**删除该文件重启即可**（会重新建库播种）。

### 管理端（三选一）

平台 API 首次启动会自动建表并播种默认管理员（`admin / Admin@123`，生产必须改）。

**方案 A：Docker 起 MySQL（推荐，零安装）**

```powershell
docker compose -f deploy/platform/docker-compose.yml up -d mysql
```

该 compose 的 MySQL 服务会创建 `station_platform` 库、`station` 用户、密码 `Station@123`，
与 `src/Station.Platform/Station.Platform.Api/appsettings.json` 的默认连接串**完全一致**，API 直接可连。
（`docker-compose.yml` 里的 `api` 服务是给部署用的镜像构建，本地开发**不需要**起它。）

**方案 B：Docker 起 PostgreSQL**

```powershell
docker compose -f deploy/platform/docker-compose.pg.yml up -d postgres
```

用 PG 时需要把 API 的数据库配置切到 PostgreSQL：

```powershell
# 方式一：环境变量（推荐，不改源码）
$env:STATION__DB__PROVIDER = "PostgreSQL"
$env:STATION__DB__CONNECTIONSTRING = "Host=127.0.0.1;Port=5432;Database=station_platform;Username=station;Password=Station@123"
# 方式二：直接改 appsettings.json（注意不要提交）
#   "Provider": "PostgreSQL", "ConnectionString": "Host=127.0.0.1;Port=5432;..."
```

**方案 C：金仓（KingbaseES）**

参考 `docs/03开发环境搭建 — WSL2与KingbaseES V8R6 安装运维手册.md`；连接串 `DbType=Kdbndp` 兼容串。

## 四、桌面端开发（目标 1）

### 运行

- **IDE**：打开 `Station.Desktop.sln`，把启动项目设为 `Station.Desktop.UI`，按 F5。
  `src/Station.Desktop/Station.Desktop.Bootstrapper/appsettings.json` 会随构建复制到输出目录。
  注意进程**工作目录**决定它是否被加载：VS 默认工作目录为输出目录（配置生效）；
  Rider 默认工程目录（配置可能不加载）——若改了配置没生效，把运行配置的工作目录改成输出目录，
  或复制一份 `appsettings.json` 到工程目录。
- **命令行**：

  ```powershell
  # 注意：dotnet run 的工作目录 = 命令执行目录，appsettings.json 按执行目录查找
  # 推荐在 Bootstrapper 目录执行，让桌面端配置生效：
  cd src\Station.Desktop\Station.Desktop.Bootstrapper
  dotnet run --project ..\Station.Desktop.UI\Station.Desktop.UI.csproj
  ```

### 启动后会发生什么

1. Avalonia 桌面窗口打开；
2. **单机版内置 Web 自动启动**在 `http://127.0.0.1:5000`（`Station:Web:Port`，见 `WebOptions`）；
3. SQLite 自动建库、播种 `admin / Admin@123`（桌面端与平台端共用同一播种逻辑）。

### 关键配置（Bootstrapper/appsettings.json）

| 配置项 | 默认 | 说明 |
| :--- | :--- | :--- |
| `Station:Db` | Sqlite / `Data Source=station.db` | 相对路径会自动重定位到数据目录 |
| `Station:Collect:SimulatedFileCount` | 5 | **模拟采集源**：不插真实执法记录仪也能产生采集文件，开发调试利器 |
| `Station:Platform:Enabled` | false | 单机模式；联调平台端时改为 true 并设 `BaseUrl` |
| `Station:Auth:AutoLogoutMinutes` | 1 | 空闲自动登出，调试期可改为 0 关闭 |
| `Station:Web:Port` | 5000 | 内置 Web 端口；`EnableLan=true` 开启局域网（强制 HTTPS，端口 5443） |

### 调试

- C# 断点：桌面端逻辑在 `Station.Desktop.Application/Infrastructure`；内置 Web 的 Controller 在 `Station.Desktop.WebHost/Controllers/`（如 `AuthController`、`FilesController`），F5 断点即可；
- XAML 调试：VS/Rider 支持 Avalonia XAML 热重载（改 `*.axaml` 即时生效）；
- 日志：Serilog 文件日志（`logs/` 目录，已被 .gitignore 忽略）。

### 常见坑

- 端口 5000 被占用：改 `Station:Web:Port` 或关掉占用进程；
- 配置没生效：检查执行目录下是否有 `appsettings.json`（见上文命令行注意事项）；
- 想完全重置：删除数据目录下 `station.db` 后重启。

## 五、管理端后端开发（目标 2）

### 运行

- **IDE（推荐）**：打开 `Station.Platform.sln`，启动项目 `Station.Platform.Api`，F5；
- **命令行**：

  ```powershell
  dotnet run --project src\Station.Platform\Station.Platform.Api\Station.Platform.Api.csproj
  ```

启动后监听 `http://127.0.0.1:5100`（`appsettings.json` 的 `Urls` 字段），首次启动自动建表 + 播种。

### 验证

```powershell
# 健康检查（平台 API：api/health；桌面端内置 Web：http://127.0.0.1:5000/api/health）
Invoke-RestMethod http://127.0.0.1:5100/api/health

# 发布产物冒烟（可选，先 dotnet publish 再跑）
powershell -File scripts/smoke-published-api.ps1
```

### 关键配置（appsettings.json / 环境变量）

| 配置项 | 默认 | 说明 |
| :--- | :--- | :--- |
| `Urls` | `http://127.0.0.1:5100` | 监听地址端口 |
| `Station:Db:Provider` / `ConnectionString` | MySql / localhost:3306 `station_platform` | 三库切换见第三章 |
| `Platform:Command:PrivateKeyPem` | 空 | 指令签名私钥；**留空即开发模式**，本地开发无需配置 |
| `Platform:Reporting:PublicKeyPem` | 空 | 上报验签公钥；同上，留空可开发 |

环境变量覆盖方式：配置节用 `__` 连成环境变量名，如 `STATION__DB__CONNECTIONSTRING`、`PLATFORM__COMMAND__PRIVATEKEYPEM`。

### 调试

- C# 断点：`Station.Platform.Api/Controllers/`（如 `StationsController`）、`Station.Platform.Application/`；
- 实时推送（SignalR）：hub 路径 `/hubs/stations`，可在浏览器控制台 `new WebSocket` 或前端页面观察；
- 数据库：表结构由实体自动生成（SqlSugar CodeFirst），`EnsureColumn` 幂等补列，升级不丢数据。

## 六、单机版内置 Web 前端开发（目标 3，station-web）

> 前置：**桌面端应用正在运行**（提供 `127.0.0.1:5000` 的 `/api` 接口）。

```powershell
# 仓库根执行
pnpm --filter station-web dev
```

- 开发服务器：`http://localhost:5174`，`/api` 自动代理到 `http://127.0.0.1:5000`（见 `station-web/vite.config.ts`）；
- 登录：`admin / Admin@123`（桌面端播种的账号）；
- 保存即热更新（HMR），页面在浏览器 F12 调试，Network 面板可看到代理后的接口调用。

### 构建与同步

```powershell
# 构建（vite build + vue-tsc 类型检查），产物直接写入桌面端 WebHost 的 wwwroot
pnpm --filter station-web build

# 或使用官方同步脚本（构建 + 校验 wwwroot；打包/发布前执行）
powershell -File scripts/sync-station-web.ps1
```

`src/Station.Desktop/Station.Desktop.WebHost/wwwroot/` 是**入库的构建产物**（随桌面端发布内嵌）。
改动前端后若需交付，按 `docs/07` 提交同步后的 wwwroot。

## 七、管理平台 Web 前端开发（目标 4，station-platform-web）

> 前置：**平台 API 正在运行**（`127.0.0.1:5100`，见第五章），且数据库已就绪（第三章）。

```powershell
# 仓库根执行
pnpm --filter station-platform-web dev
```

- 开发服务器：`http://localhost:5173`，`/api` 与 `/hubs`（SignalR WebSocket）代理到 `http://127.0.0.1:5100`；
- 登录：`admin / Admin@123`；
- 依赖 ECharts、Element Plus 等，页面包含监控大屏（`StatsView`）、站点管理（`StationsView`）、指令下发（`CommandsView`）等。

### 构建

```powershell
pnpm --filter station-platform-web build
```

产物直接写入 `src/Station.Platform/Station.Platform.Api/wwwroot/`（入库），平台后端静态托管，哈希路由深链无需后端回退配置。

## 八、常见问题速查

| 现象 | 处理 |
| :--- | :--- |
| `pnpm` 不是内部或外部命令 | `npm install -g pnpm`（或 `corepack enable`），版本 9.x |
| `pnpm install` 慢 / 超时 | 配置镜像源：仓库根建 `.npmrc` 写 `registry=https://registry.npmmirror.com`（仅个人用，勿提交） |
| `dotnet restore` 拉包失败 | 检查网络/代理；或配置国内 NuGet 镜像源（NuGet.Config，个人用） |
| 前端页面接口 502 / 代理失败 | 后端没起：目标 3 需要桌面端在跑（5000），目标 4 需要平台 API 在跑（5100） |
| 端口被占用（5000/5100/5173/5174） | 换端口：后端改 `appsettings.json` 的 `Urls` / `Station:Web:Port`；前端改 `vite.config.ts` 的 `server.port` 与 proxy target |
| 平台 API 启动报数据库连接失败 | 先 `docker compose -f deploy/platform/docker-compose.yml up -d mysql`；核对连接串与 `.env` |
| 桌面端报错 / 白屏 | 看 `logs/` 日志；确认数据目录权限；`STATION__DATA__DIR` 可指向本地可写目录 |
| 改了 `packages/shared` 只测了一端 | 共享包改动影响两个前端，必须 `pnpm -r typecheck` 两端一起过 |
| 修改 `api/types.ts` 报类型错误 | 全局 typecheck（`pnpm -r typecheck`），别只看当前文件 |
| 提交里出现 `wwwroot` 或 `package-lock.json` 变更 | 前者按 `docs/07` 决定是否入库；`package-lock.json`（npm 旧锁）已废弃，用根 `pnpm-lock.yaml` |
| 桌面端与平台端版本号 | 互不相关：桌面端看 `src/Station.Desktop/Directory.Build.props`，平台端看 `src/Station.Platform/Directory.Build.props` |
