# M52：工作台 30 路 USB 采集卡片 + 状态监控崩溃修复

> 状态：✅ 通过（2026-08-16，桌面全量构建 + linux-x64 发布 + M51 spike 回归 12/12）
> 目标：修复工作台状态监控 `MonitorLines[0]` 越界崩溃；按原型"桌面端工作台"将工作台改为 30 路 USB 采集通道卡片展示。

## 1. 崩溃修复（MonitorLines 越界）

- 原 [WorkbenchView.axaml](../../src/Station.Desktop/Station.Desktop.UI/Views/WorkbenchView.axaml) 直接绑定 `MonitorLines[0..5].Value`，首次渲染或监控快照为空时 Avalonia 绑定抛 `ArgumentOutOfRangeException`；
- 改为命名可观察属性（`CpuText/MemText/DiskText/NetText/PortsText/DeviceText`），刷新时按索引安全取值（`lines.Count > index ? value : "—"`），不再依赖集合索引绑定。

## 2. 工作台 30 路 USB 卡片（对齐原型"桌面端工作台"）

### 布局

- 顶部统计卡：本机运行（授权状态）、今日采集（个数/容量）、待上传、USB 端口状态（采集中/已暂停/空闲）；
- 本机监控行：CPU/内存/磁盘/网络/监听端口/设备；
- 主体：5 列 × 6 行 = **30 路 USB 采集通道卡片**（滚动区，空闲卡片降透明度）。

### 卡片内容（`UsbPortCardViewModel`）

- 端口号（#01~#30）+ 状态徽标（采集中/已暂停/已完成/故障/空闲，配色区分）；
- 设备名（占位"等待设备连接"）、协议（UMS/MTP/私有SDK）+ 自动/手动、文件数与已采集容量；
- 进度条 + 百分比 + 速度（MB/s）；
- 操作：暂停/恢复/取消/重试（权限：登录 + file:manage，即 collect 模块权限）；"明细"弹出任务文件窗口（文件名/大小/状态/时间）。

### 端口映射策略

- 端口→任务映射按任务 ID 保持稳定：任务进行中刷新卡片，任务结束/拔出后该端口回空闲；
- 新任务自动分配到第一个空闲端口（`GetActiveTasksAsync` 返回扫描/采集中/已暂停任务）；
- `CollectTaskDto` 增加 `Protocol` 字段用于卡片协议展示。

## 4. 说明

- 30 路为固定通道展示；当前端口占用来源于真实采集任务，任务状态由采集服务实时驱动，无设备时显示"等待设备连接"；
- 记录仪电量、紧急优先等原型展示项因设备端无上报数据暂不实现。
