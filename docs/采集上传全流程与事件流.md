# 采集上传全流程与事件流

> 适用范围：单机 30 路 USB 并发，SqlSugar + 领域事件（Channel 模式）
> 阶段一：无 Outbox，事件丢失窗口 ≤ 200ms

## 六、数据库写入清单（30 路 USB 并发）

| 表                               | 写入时机            | 频率                        | 方式                                         |
| -------------------------------- | ------------------- | --------------------------- | -------------------------------------------- |
| `station_collect_task`           | 创建任务            | 每任务 1 次                 | 短连接 INSERT                                |
| `station_collect_task`           | 状态迁移            | 每任务 ≤ 8 次               | 短连接 / 长连接 UPDATE                       |
| `station_collect_task`           | 进度累加            | 每任务 ≤ 5 次/秒            | **长连接原子 UPDATE**（`IncrementProgress`） |
| `station_collect_task`           | 终态                | 每任务 1 次                 | **长连接整行 UPDATE**（覆盖内存累计值）      |
| `station_collect_file`           | 扫描完成            | 每任务 1 次批量             | 短连接 INSERT RANGE                          |
| `station_collect_file`           | 单文件开始          | 每文件 1 次                 | 长连接 UPDATE                                |
| `station_collect_file`           | 单文件进度          | 每文件 ≤ 10 次              | 长连接 UPDATE（10% 档）                      |
| `station_collect_file`           | 单文件完成          | 每文件 1 次                 | 长连接 UPDATE                                |
| `station_collect_file`           | 上传状态变化        | 每文件 ≤ 3 次               | 长连接 UPDATE                                |
| `station_uploaded_file`          | 上传成功            | 每文件 1 次                 | 短连接 INSERT（幂等）                        |
| `station_audit_log`              | 状态迁移 / 上传完成 | 每任务 ≤ 8 次 + 每文件 1 次 | 短连接 INSERT                                |
| `station_event_outbox`（阶段二） | 关键事件            | —                           | 事务内 INSERT                                |

**关键设计**：
- 进度字段用 `CollectedFiles = CollectedFiles + @delta` 原子累加，避免读改写竞争
- 状态字段走 `UpdateStateOnly`，白名单列，不碰进度字段
- 终态整行 `Update`，用内存累计值覆盖 Aggregator 的延迟

## 七、性能设计要点

| 挑战                          | 方案                                         | 效果                |
| ----------------------------- | -------------------------------------------- | ------------------- |
| 30 路 USB 每秒 60+ 次进度事件 | 聚合内节流 10%（采集）/ 5%+500ms（上传）     | 降到 ≤ 5 次/秒/文件 |
| Task 行锁竞争                 | `IncrementProgress` 原子 UPDATE + 200ms 合并 | 30 路合并为 5 次/秒 |
| UI 刷新噪声                   | ViewModel 150ms 合并 + 去噪阈值 0.1 MB/s     | UI 稳定             |
| 事件总线阻塞                  | Channel 有界 `TryWrite`，非阻塞              | 生产者永不卡        |
| Handler 阻塞                  | 所有 handler 无 DB I/O 或走独立 scope        | 派发线程快速        |
| 后台采集线程饥饿              | `TaskCreationOptions.LongRunning` 专用线程   | 不占线程池          |
| 长连接与短连接竞争            | 主线程走短连接 UoW，后台走长连接             | 互不干扰            |
| 数据库压力                    | 详见第六节                                   | 峰值 ≤ 200 次/秒    |

## 八、事件时序（关键路径）

### 8.1 文件采集完成

```
CollectTaskService.RunCollectAsync
  │
  ├─ file.CompleteCollecting(...)
  │     └─ Raise(CollectFileCollected)
  │
  ├─ fileSync.Update(file)               ← 长连接 UPDATE
  │
  ├─ PublishAndClearEvents(file)          ← fire-and-forget
  │     │
  │     └─ IDomainEventBus.PublishRangeAsync
  │           │
  │           └─ ChannelDomainEventBus.TryWrite
  │
  ├─ task.AddCollectedFile(fileSize)      ← 仅内存
  │
  └─ 循环下一文件

ChannelEventDispatcher（独立 HostedService，100ms 批次）
  │
  ├─ reader.ReadAsync → 批量凑齐 200 条或超时
  │
  └─ DispatchBatchAsync
        │
        ├─ ProgressAggregator.HandleAsync
        │     └─ 内存累加 (Interlocked)
        │
        └─ DomainEventToUiBridge.HandleAsync
              └─ IUsbPortCardEventService.PublishTaskFileCompleted

ProgressAggregator（独立循环，200ms）
  │
  ├─ Drain 所有 Accumulator
  │
  ├─ taskSync.IncrementProgress(...)      ← 原子 UPDATE + SELECT 快照
  │
  └─ bus.PublishRangeAsync(CollectTaskProgressChanged)   ← 无订阅者，预留
```

### 8.2 任务完成

```
CollectTaskService.FinalizeAsync
  │
  ├─ 无未完成文件
  │
  ├─ task.Complete(now)
  │     ├─ TransitionTo(Completed)
  │     │    └─ Raise(CollectTaskStatusChanged)
  │     └─ Raise(CollectTaskCompleted)
  │
  ├─ taskSync.Update(task)               ← 整行写，覆盖进度
  │
  ├─ PublishAndClearEvents(task)
  │     │
  │     └─ Channel.Write
  │
  └─ 清理 _controls

ChannelEventDispatcher
  │
  ├─ AuditOnCollectTaskStatusChanged → AuditLog
  ├─ SyncOutboxOnCollectTaskCompleted → SyncOutbox
  ├─ DomainEventToUiBridge → PublishTaskStatus
  └─ （Completed 事件无 ProgressAggregator 订阅）
```


| 配置                      | 默认       | 说明                                            |

| `RetentionDays`           | 30         | 内存事件保留（阶段一）                          |
| `OverflowPolicy`          | DropOldest | 队列满策略                                      |

## 十、关键不变量

1. **聚合根是唯一状态修改入口**：外部不能直接赋值 `Status` / `Progress`
2. **领域事件在聚合内 Raise**：应用服务不手工构造领域事件
3. **事件发布与 DB 写入解耦**：发布失败不回滚 DB，Aggregator 处理失败记日志不重投
4. **进度字段只由 Aggregator 写**：主线程不写进度列（避免覆盖）
5. **终态整行写**：任务完成 / 失败时用内存精确值覆盖
6. **UI 事件与领域事件分离**：UI 事件进程内同步，领域事件走 Channel
7. **实时进度绕过总线**：`CopyAsync` 回调直接调 `PublishTaskProgress`，不进领域事件
