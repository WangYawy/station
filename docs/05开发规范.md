# 视音频数据采集站与监控管理平台 — 开发规范

> 版本：0.1.0（基线）　适用：桌面端 + 单机版内置 Web + 监控管理平台
> 配套：《Git 与协作规范》《CI 与发布规范》《日常开发流程与检查清单》

## 一、总体原则

1. **一切以可交付为准**：代码必须能构建、能运行、能交付（跨平台 / 信创 / 三库兼容）；
2. **分层清晰、依赖单向**：Shared 是公共契约层，任何一端不得反向依赖；
3. **安全优先**：国密算法、验签、脱敏、审计是硬性要求，不是可选项；
4. **可维护性**：命名、日志、里程碑文档与代码同步更新，提交可回溯。

## 二、工程结构与依赖方向

### 解决方案与工程

| 解决方案 | 包含工程 | 定位 |
| :--- | :--- | :--- |
| `Station.Desktop.sln` | `Station.Desktop.UI` / `Bootstrapper` / `Application` / `Infrastructure` / `WebHost` | 采集站桌面端（含单机版内置 Web） |
| `Station.Platform.sln` | `Station.Platform.Api` / `Application` / `Domain` | 监控管理平台后端 |
| 共享层 | `Station.Shared`：`Contracts` / `Domain` / `Application` / `Infrastructure` | 两端共享的模型、契约与基础设施抽象 |

### 依赖方向（红线）

```text
Station.Desktop ──┐
                  ├──> Station.Shared   （共享层不依赖任何一端）
Station.Platform ─┘
```

- `Desktop → Shared`、`Platform → Shared`，反向禁止；
- **`Platform` 永不引用 `Desktop`**；需要共享的模型/逻辑一律下沉到 Shared；
- `archive/` 仅为历史参考，**不参与构建、不纳入交付**；
- `spikes/` 为一次性验证工程，用于里程碑风险验证，不进入正式交付产物；
- 新增代码必须落入对应层，禁止跨层引用（Controller/UI 只做编排，不写业务逻辑）。

### 分层职责

| 层 | 职责 | 禁止 |
| :--- | :--- | :--- |
| `Contracts` | 跨端 DTO、枚举、指令/回执契约、ini 绑定格式 | 依赖具体实现 |
| `Domain` | 实体、聚合根、枚举、领域规则 | 依赖基础设施/UI |
| `Application` | 用例编排、服务、校验 | 直接写 SQL、直接操作设备 |
| `Infrastructure` | 数据持久化、设备驱动（UMS/MTP/SDK）、存储、安全、备份 | 被其他层直接 new |
| `UI / WebHost / Api` | 展示与宿主，注入并调用 Application | 承载业务逻辑 |

## 三、C# 编码规范

### 工程基线（由 `Directory.Build.props` 统一）

- `net8.0`、`Nullable enable`、`ImplicitUsings enable`、`LangVersion latest`；
- `TreatWarningsAsErrors=false`：警告不阻断构建，但**新增代码不允许引入新警告**；
- 格式以 `.editorconfig` 为唯一事实来源：UTF-8、CRLF、C# 4 空格缩进、文件末尾换行；
- C# 命名空间使用 **file-scoped**（`.editorconfig` 已置为 warning）。

### 命名约定

| 对象 | 约定 | 示例 |
| :--- | :--- | :--- |
| 类型 / 方法 / 公共属性 | PascalCase | `RecorderService`、`IdentifyAsync` |
| 局部变量 / 参数 | camelCase | `recorderId` |
| 私有字段 | `_` + camelCase | `_connectionString` |
| 接口 | `I` 前缀 | `ICollectSource` |
| 异步方法 | `Async` 后缀 | `UploadAsync` |
| 常量 / 静态只读 | PascalCase | `DefaultOnlineTimeoutSeconds` |

### 异步与并发

- 全程异步，禁止 `sync-over-async`（`.Result` / `.Wait()`）；
- 采集、上传等 I/O 密集路径使用异步管道（Pipelines）、分块读写、断点续传；
- 共享状态通过锁或不可变设计保护；30 路并发按接口验收标准执行；
- 平台相关能力（WMI / udev / WPD / MTP）必须隔离在 Infrastructure 并提供抽象，非 Windows 平台抛出明确的 `PlatformNotSupportedException`。

### DI 与组合根

- 构造函数注入，禁止 ServiceLocator / 静态服务；
- 注册集中在 `Bootstrapper` / `Program.cs`（组合根），按"应用服务优先、基础设施兜底"的顺序注册，避免桌面端覆盖共享层默认注册。

### 异常、校验与日志

- DTO 入参校验用 FluentValidation；业务失败返回明确错误码/消息，异常只留给非预期路径；
- 禁止空 `catch` 吞异常；捕获后必须记录或重新抛出；
- 日志用 Serilog 结构化模板（`{StationId}`、`{TaskId}` 等），禁止字符串拼接；
- **禁止记录**：密码、私钥、授权原文、脱敏字段原文。

### 契约变更

- `Station.Contracts` 的任何变更都是跨端契约变更：必须同时检查 Desktop / Platform / 前端消费方；
- 变更记录写入对应里程碑文档；协议级修改（指令、上报、签名）必须 Spike 先行并回归联调。

## 四、前端规范（Vue 3 + TypeScript）

### 工程结构（`station-web` 与 `station-platform-web` 一致）

```text
src/
├── api/       client.ts（axios 实例 + 拦截器）、types.ts（接口类型）
├── layouts/   布局组件（AdminLayout 等）
├── router/    路由
├── stores/    Pinia 状态（auth 等）
├── utils/     工具（format、export、realtime）
└── views/     页面（PascalCase，如 AlertsView.vue）
```

### 约定

- 使用 `<script setup lang="ts">` + 组合式 API；
- 组件/页面文件 **PascalCase**；变量/函数 camelCase；
- 接口类型集中在 `api/types.ts`，禁止裸 `any`（确有需要时注释说明）；
- 请求统一走 `api/client.ts`，禁止页面散落裸 `fetch`；
- 全局状态用 Pinia，组件间通信避免直接改写 store 之外的状态；
- 平台前端实时刷新统一走 `utils/realtime.ts`（SignalR 按事件类型分发，页面卸载自动退订）；
- 图表使用 ECharts 按需引入（M27 已落地），新增依赖需说明理由；
- 页面/路由/菜单命名与后端模块一一对应，新增 API 先改 `types.ts`。

### 提交前质量门禁

```powershell
npm run typecheck   # vue-tsc --noEmit
npm run build       # vite build && vue-tsc --noEmit
```

- 不提交 `node_modules/`、`dist/`、`.vite/`；
- 修改 `api/types.ts` 后必须全局 typecheck，防止漏改调用方。

## 五、数据库与数据访问规范

- SqlSugar + CodeFirst：实体即表结构，业务层自动建表/补列；
- 表结构演进必须**幂等**（`EnsureColumn` 风格补列），升级不丢数据；
- **三库适配**（MySQL 8 / PostgreSQL / Kingbase）与本地库（SQLite/Kingbase）：
  - 使用 SqlSugar 跨库能力，禁止写死方言 SQL、存储过程、触发器；
  - 新增 SQL 至少 MySQL + PostgreSQL 各验证一次，有金仓环境则三库全验；
  - 金仓连接使用 Kdbndp 驱动、`DbType=Kdbndp` 兼容串；
- 主键/业务键稳定；审计字段（创建/更新/操作人）由公共基类或拦截器统一维护；
- 索引按查询路径命名（`idx_<table>_<cols>`），避免冗余索引；
- 列表/导出一律分页 + 条件过滤，禁止全表拉取；
- 敏感字段**存原文、输出时脱敏**（展示/导出）；授权、凭据、缓存等敏感信息 SM4 加密存储。

## 六、安全规范

| 场景 | 算法/要求 |
| :--- | :--- |
| 远程指令、授权文件、上报签名、文件归属修正 | SM2 签名/验签；**验签失败必须拒绝执行并留审计** |
| 台账校验、上传远端二次校验、机器指纹 | SM3 |
| 缓存 / 凭据 / 授权信息 | SM4 加密存储 |
| 用户口令 | bcrypt 哈希，禁止明文或可逆存储 |

- 私钥只放环境变量或受控配置文件（如 `PLATFORM_COMMAND_PRIVATE_KEY`），**禁止进入仓库**；
- 生产必须配置指令签名私钥与上报验签公钥，否则以开发模式运行（交付检查项）；
- 访问控制：登录认证 + RBAC + 数据范围（部门树隔离）；接口、导出、预览均按角色/数据范围校验；
- 通信默认 HTTPS（自签名或正式证书），局域网可配置；
- 关键操作必须留痕：登录、配置变更、远程指令、报警处置、导出等（审计日志可追溯、不可删）；
- 授权到期瞬间**立即中断进行中的采集**，不得延迟。

## 七、日志与可观测性

- Serilog 结构化日志：模板参数记录上下文（`stationId` / `taskId` / `alertId`）；
- 文件日志按天滚动 + 大小限制，异步写入；
- 平台健康检查：`GET /api/v1/health`；
- 在线率由心跳维持（默认 5 分钟超时，`Platform:OnlineTimeoutSeconds` 可调）；
- 存储熔断：上传连续失败达阈值自动熔断，冷却后自动恢复并补传。

## 八、测试规范（目标）

- 单元测试：xUnit + NSubstitute + Shouldly；
- API 集成测试：Microsoft.AspNetCore.TestHost；
- 优先覆盖：领域规则、SM2/SM3/SM4、脱敏、数据范围、幂等迁移、指令验签拒绝路径；
- 高风险/新技术点先建 `spikes/` 一次性工程验证（场景/结果表格记入里程碑文档），再落地正式实现；
- 现状：主源码暂未建测试项目（archive 有遗留测试工程），新里程碑应逐步补齐，接入 CI 见《CI 与发布规范》。
