## 一、项目概述与建设目标

本项目建设"视音频数据采集站与监控管理平台"，面向执法记录仪等视音频设备的数据采集、存储、查看、监管和基础运维场景，交付一个可在真实客户环境中试点落地的 MVP 版本。

MVP 的核心目标是跑通以下业务闭环：

```mermaid
flowchart LR
  A[记录仪接入] --> B[身份识别<br/>ini 绑定校验]
  B --> C[自动识别]
  C --> D[文件采集]
  D --> E[完整性校验]
  E --> F[本地缓存与加密]
  F --> G[上传到存储目标]
  G --> H[文件查询与预览]
  H --> I[台账、权限、审计、报警管理]
```

本期必须同时交付三部分：

| 子系统 | 本期定位 | 优先级 |
| :--- | :--- | :--- |
| 采集站桌面端 | 数据采集、存储、状态监控、授权、登录、模式切换的核心入口 | 最高 |
| 监控管理平台 | 多采集站集中监管、台账、报警、文件检索预览、审计、基础运维 | 第二 |
| 单机版内置 Web | 单机多部门共用、权限隔离、查询、审计、基础管理 | 第三，但仍为 MVP 必交付 |

## 二、产品定位与商业模式

1. 监控管理平台为**部署在客户环境、由客户自建自管**的独立系统，客户使用它管理自家采集站；平台不是厂商集中管理客户采集站的后台。
2. 授权注册码/授权文件由**厂商内部工具**生成，与平台无关；P0 仅支持离线授权。
3. 产品面向执法记录仪数据采集场景，核心价值是"记录仪接入即采集、采集即校验、校验即归档、全程可审计"。

## 三、MVP 范围原则

### 3.1 本期必须保证

1. 采集站能够在客户实际硬件环境中完成记录仪接入、身份识别、文件采集、校验、缓存、上传、查询和报警。
2. 平台能够集中管理采集站、记录仪、用户、组织、文件元数据、报警和审计日志。
3. 单机版能够支持多部门共用同一采集站，具备部门、用户、角色和数据隔离能力。
4. 单机版与平台版统一采用 RBAC 权限模型，数据权限按组织范围与角色定义隔离。
5. 商业授权（离线授权）、安全加密、日志脱敏、基础审计、断网补传等能力必须可用。
6. 平台数据库 MySQL/PostgreSQL/Kingbase 三库均须 P0 适配；采集站本地数据库 SQLite/Kingbase 均须 P0 适配；信创（x86_64 + ARM64）为硬性验收要求。
7. 所有 P0 功能必须具备可验收标准。

### 3.2 本期控制范围

1. MVP 聚焦基础采集与监管闭环，不做复杂合规流程、自动归档引擎、远程静默升级、生物识别、LDAP/AD、第三方系统集成。
2. 视频在线播放 P0 仅保证 H.264；H.265 引导下载；转码模块放 P2 并在采集站侧实现。
3. 授权仅支持离线授权（注册码/授权文件），不支持在线激活。
4. 目标 CPU 架构 P0 为 x86_64（海光/兆芯）与 ARM64（飞腾/鲲鹏）；龙芯 LoongArch 放 P2。
5. 采集不做字节级断点续采（半截文件作废重采）；上传做断点续传/分片。
6. P0 不做记录仪校时；采集时间以采集站系统时间为准。
7. 技术实现以可落地和可验收为优先，不追求一次性覆盖所有高阶扩展能力。
8. 平台实时性以稳定可靠为优先，P0 采用 HTTPS API 上报、心跳/指令独立轮询和本地持久化补传队列；SignalR/WebSocket 实时推送作为 P1。

## 六、系统形态与边界

### 6.1 采集站桌面端

采集站桌面端是本项目最高优先级子系统，负责设备接入、身份识别、文件采集、完整性校验、本地缓存、上传、状态监控、报警、自检、授权、登录和单机/平台模式切换。

桌面端采用单一安装包，通过运行模式配置切换单机版和平台版，切换后重启生效。切换时本地已有文件元数据和台账是否迁移上报平台、切回单机版时本地数据保留还是清空，均为可配置项。

| 模式 | 数据与配置来源 | 主要行为 |
| :--- | :--- | :--- |
| 单机版 | 本地数据库 | 本地认证、本地台账、本地查询、本地权限隔离 |
| 平台版 | 平台配置为主，本地缓存为辅 | 从平台同步组织、用户、记录仪、授权名单、账号和采集策略（本地只读，修改必须去平台）；断网时本地缓存继续支撑采集 |

**桌面端登录机制**：

1. 免登录 / 必须登录两种模式，通过配置切换。
2. 免登录模式下，采集任务"操作人"通过两种可配置模式确定：①记录仪绑定用户（ini 绑定，见 10.1）；②采集时手选用户。
3. 必须登录模式下，所有导航与主界面操作按钮均需登录后才能操作；登录后 1 分钟无操作自动退出登录。
4. 桌面端账号与单机版内置 Web、平台账号为同一套用户体系；平台模式下账号数据由平台同步到本地，登录始终在本地验证，不依赖平台在线。

### 6.2 单机版内置 Web

单机版内置 Web 是嵌入采集站桌面端的本地 Web 服务，用于单机多部门共用场景。默认仅允许本机访问，可由管理员配置开启局域网访问。开启局域网访问后必须启用 HTTPS、登录认证和访问日志。

单机版与平台版统一采用 RBAC 权限模型，预置角色与平台一致（见 10.7）。单机 Web 保持轻量级部门列表，不引入平台侧复杂多级组织树。

### 6.3 监控管理平台

监控管理平台是部署在客户环境、由客户自建自管的独立 B/S 系统，用于集中管理多台采集站及其数据，提供组织、用户、记录仪、采集站、文件、报警、审计和基础运维管理。

平台支持多级组织树，不限制层级。账号、用户、记录仪、采集站均可挂接到组织节点，数据权限按组织树继承（上级可看全部下级数据，下级不可见上级/平级，同级隔离）。

## 七、P0 必交付范围

### 7.1 采集站桌面端 P0

| 模块 | P0 范围 | 验收标准 |
| :--- | :--- | :--- |
| 设备接入 | 支持 USB Mass Storage、MTP、私有加密（SDK 可将设备转为 UMS 模式）三类协议 | 至少在客户提供的目标记录仪样机上完成识别、文件枚举和基础元数据读取 |
| 文件类型 | 视频（.mp4/.avi/.flv/.mov）、音频（.wav/.mp3/.aac）、图像（.jpg/.bmp/.jpeg/.png）；支持扩展其他类型（如 .log） | 可采集、筛选、预览清单内全部类型文件 |
| 身份识别与归属 | 记录仪根目录 ini 绑定（记录仪编号、用户、部门、绑定时间 + SM3 校验）；接入时三层识别：无 ini=未绑定、ini 校验失败=疑似篡改、编号不在台账/白名单=非授权接入 | 已绑定设备正确识别归属；未绑定设备默认拒绝采集并报警；绑定不一致时按台账自动重写 ini |
| 并发采集 | 按客户实际采集站硬件接口数验收；架构预留 30 路 | 实际接口数并发采集时，单路异常不影响其他通道 |
| 采集触发 | 记录仪接入自动开始（默认）、手动开始、后台任务定时开始 | 三种触发方式均可用；定时任务可配置 |
| 文件采集 | 全量扫描采集；已采集文件自动跳过（去重）；支持暂停、恢复、取消 | 文件可完整采集到本地缓存，并记录采集状态 |
| 任务状态机 | 每次记录仪连接 = 一次采集任务；文件级状态：待采集→采集中→SM3 校验→待上传→上传中→已完成，另有中断/异常/跳过 | 任务与文件状态可查询；中断/异常/跳过均有明确记录 |
| 中断处理 | 设备拔出仅中断"设备→本地缓存"段；半截文件作废删除、下次接入重新采集（不做字节级续传）；上传队列独立于设备继续后台补传 | 模拟中途拔线：半截文件不误判为已采集；已完整落缓存文件继续上传 |
| 完整性校验 | 每个文件计算 SM3 哈希；上传完成后对远端文件做 SM3 二次校验 | 采集完成后可查看文件哈希和校验结果；远端校验不一致按上传失败处理 |
| 本地缓存加密 | 文件缓存使用 SM4 加密；凭据使用 SM4 加密存储 | 本地缓存和 FTP/SFTP 凭据不以明文形式存储 |
| 缓存清理 | 按保留天数清理本地加密缓存（默认 30 天，可配置） | 超过保留天数的已上传缓存文件被清理并留审计 |
| 存储目标 | 同时支持本地磁盘、FTP、SFTP；上传目录结构支持管理员自定义模板（{采集站编号}/{日期}/{记录仪编号}/{用户编号}/{部门}/{文件类型}） | 三类目标均可配置、连通性测试、上传和失败重试 |
| 大文件上传 | FTP/SFTP 支持断点续传/分片；断网恢复后接着传 | 模拟断网：大文件断网恢复后继续传输，不整文件重传 |
| 断网补传 | 上传失败时本地滞留；网络恢复事件触发补传；重试次数/间隔在采集策略中可配置 | 模拟网络中断后，恢复网络可继续上传未完成文件 |
| 存储熔断 | P0 简单版：同一存储目标连续失败达阈值（默认 5 次）熔断（默认 10 分钟），到期自动恢复，熔断期间报警 | 存储不可达时触发熔断并报警；恢复后自动解除 |
| 采集后擦除 | 按部门配置是否启用擦除；启用后任务完成自动擦除该记录仪本次已采集的全部文件（不保留最近 N 天） | 仅在采集完成、校验通过、远端二次校验通过、存储成功后允许擦除；执行前二次确认并留审计 |
| 擦除失败处理 | 单个文件删除失败：重试→跳过并报警，不阻塞任务完成 | 部分文件删除失败时任务正常关闭，报警可查，其余文件仍被删除 |
| 状态监控 | 显示 CPU、内存、磁盘、网络、端口、设备、采集进度 | 可在桌面端查看当前采集站健康状态和通道状态 |
| 本地报警 | 磁盘不足、网络中断、USB 故障、校验失败、非授权接入、绑定信息异常、存储不可达、授权过期；阈值在采集策略中可配置 | 报警可展示、可确认、可处理、可关闭，可跳转到处理入口；同类报警未关闭前自动去重 |
| 报警通知 | 界面列表 + 声音提示 + 弹窗 | 新报警触发声音和弹窗提示 |
| 系统设置与自检 | 采集站编号、单位、模式、平台连接、存储目标、清理策略、授权信息、自检报告 | 可生成包含 USB、磁盘、网络、存储、授权状态的自检结果 |
| 授权机制 | 30 天试用、7 天宽限、到期锁定采集；离线授权文件/注册码（厂商内部工具生成）；机器指纹绑定（CPU+主板+磁盘+MAC 组合）；一台一码；换硬件需重新授权；时钟回拨检测；到期瞬间立即中断当前采集 | 完整演示试用、宽限、锁定、离线激活和回拨锁定链路 |
| 桌面端登录 | 免登录/必须登录可配置；必须登录时所有导航和操作按钮需登录；1 分钟无操作自动退出 | 两种模式切换后行为符合定义；自动退出生效 |
| 数据库适配 | 默认 SQLite，同时 P0 支持 Kingbase；数据访问层必须可替换 | 核心本地数据在 SQLite 与 Kingbase 下均可读写 |
| 本地备份 | 本地数据库每日自动备份，保留最近 7 份 | 备份文件可恢复；备份动作留审计 |
| 跨平台运行 | Windows 10/11、Ubuntu、麒麟、统信 UOS（x86_64 + ARM64） | 在客户指定版本完成安装、启动、采集和基础功能验证 |

### 7.2 单机版内置 Web P0

| 模块 | P0 范围 | 验收标准 |
| :--- | :--- | :--- |
| 访问方式 | 默认仅本机访问，可配置局域网访问 | 默认局域网不可访问；开启后可通过内网地址访问，且启用 HTTPS、认证与访问日志 |
| 登录认证 | 用户登录、失败锁定、防暴力破解 | 连续失败 5 次锁定账号 15 分钟 |
| 部门管理 | 轻量级部门列表增删改查 | 可创建多个部门并分配账号、用户、记录仪 |
| 账号与角色 | 统一 RBAC：管理员、部门负责人、操作员、审计员四种预置角色 + 管理员自定义角色与权限点 | 不同角色登录后菜单、数据范围和操作权限符合定义 |
| 用户台账 | 本地维护简化用户信息 | 可导入、维护用户并绑定部门/记录仪 |
| 记录仪绑定 | 记录仪与用户/部门绑定；提供"写入绑定"将绑定信息写入已连接记录仪根目录 ini | 采集文件可自动继承归属；ini 写入后识别正确 |
| 数据隔离 | 管理员=全部权限；部门负责人=本部门数据操作；操作员=本人数据操作；审计员=全局只读 | 使用不同账号登录后，文件列表、历史、统计、日志展示范围符合数据范围定义 |

## 十、关键业务规则

### 10.1 记录仪身份识别与文件归属（ini 绑定）

1. 记录仪身份识别载体为其根目录 ini 文件，内容包含记录仪编号、用户信息、部门信息、绑定时间及 SM3 校验值。
2. ini 由台账管理（单机版 Web / 平台）在设备已连接时通过"写入绑定"操作生成；UMS 模式下，该写入动作是台账与物理设备建立关联的唯一途径，需操作员人工确认"当前插入的即为目标记录仪"。
3. 记录仪接入采集站后的三层识别：
   - 无 ini：未绑定设备；
   - 有 ini 但 SM3 校验失败：绑定信息异常（疑似篡改）；
   - ini 有效但记录仪编号不在本地台账（单机版）或平台白名单（平台版）中，或编号已注销：非授权接入。
4. 未绑定设备默认策略为**禁止采集**（界面提示 + 报警）；"允许采集并标记待归属"为可配置策略，默认关闭。绑定信息异常与非授权接入均触发报警。
5. ini 有效且编号存在、但绑定与台账不一致时：以台账为最新依据，接入时自动重写 ini，然后正常采集。
6. 已授权设备采集的文件，归属自动继承 ini 中的用户/部门。
7. "待归属"状态仅在允许采集模式（A 模式）下或绑定信息异常时出现；管理员可修正文件归属、用户绑定、部门归属，所有修正必须留痕，平台侧关键修正（含归属修正）附带 SM2 签名。
8. 用户部门/岗位调动的历史文件归属保持采集时的组织不变。
9. 采集时间以采集站系统时间为准；记录仪文件自带的原始时间单独存储、不覆盖，检索默认按采集时间，支持按原始时间筛选。

### 10.2 采集任务与中断处理

1. 每次记录仪连接 = 一次采集任务（后台定时触发同样产生任务）。
2. 任务下每个文件有独立状态：待采集 → 采集中 → SM3 校验 → 待上传 → 上传中 → 已完成；另有中断/异常/跳过。
3. 设备拔出仅中断"设备→本地缓存"段；半截文件作废删除、文件标记"采集中断"，下次接入自动重新采集，不做字节级断点续传。
4. 已完整落缓存并通过 SM3 校验的文件，即使设备被拔出，上传继续在后台执行；上传失败留在待上传队列重试（断网补传）。
5. 任务状态：全部文件采集+上传成功 = 已完成；设备中途拔出 = 中断（未采文件下次重新扫描采集）；单文件校验失败或重试达上限仍失败 = 异常，触发报警并保留现场。
6. 已采集文件的去重依据为"完整落缓存 + SM3 通过"；半截文件不会被误判为已采集。

### 10.3 采集后擦除

1. 按部门配置"保留原件"或"采集后擦除记录仪原文件"；擦除策略默认关闭。
2. 开启擦除策略时，管理员需确认并记录审计日志。
3. 擦除时机：每次采集任务完成后自动执行。
4. 擦除范围：删除该记录仪上本次已采集的全部文件，不保留最近 N 天。
5. 仅当文件采集完成、SM3 校验通过、目标存储远端 SM3 二次校验通过、存储写入成功后，才允许擦除。
6. 每次执行擦除前必须再次确认，明确展示设备编号、文件数量、采集校验状态。
7. 单个文件删除失败：自动重试，仍失败则跳过并触发报警，不阻塞任务关闭。
8. 擦除方式为普通删除（不做覆盖式删除）。
9. 擦除操作必须记录审计日志。

### 10.4 存储与上传

1. 存储目标：本地磁盘、FTP、SFTP 三类，P0 均支持；上传目录结构由管理员自定义模板（变量：{采集站编号}/{日期}/{记录仪编号}/{用户编号}/{部门}/{文件类型}）。
2. "存储成功"判定：上传完成后对远端文件计算 SM3 与本地比对，一致才算成功；不一致按上传失败处理（重新上传 + 异常报警）。
3. FTP/SFTP 支持断点续传/分片，断网恢复后接着传，不整文件重传。
4. 上传失败文件滞留本地加密缓存；网络恢复事件触发补传；重试次数/间隔在采集策略中可配置（默认无限重试、间隔 30 秒），达上限标异常 + 报警，文件保留可手动重传。
5. 存储熔断（P0 简单版）：同一存储目标连续失败 5 次熔断 10 分钟，到期自动恢复，熔断期间报警。
6. 本地加密缓存按保留天数清理（默认 30 天），清理留审计；缓存为待上传中间态，不备份。

### 10.5 审计与脱敏

1. 日志分为三类：操作日志（即审计日志，记录人的操作）、设备日志（系统/设备事件，如 USB 插拔、磁盘 IO、网络变化、任务状态）、报警日志（报警记录）。
2. 审计日志覆盖登录、查询、导入、导出、删除、擦除、配置修改、绑定写入、归属修正、远程指令等关键操作。
3. 审计日志字段：时间、操作人（账号+姓名）、来源 IP/终端、操作类型、操作对象、操作详情、结果（成功/失败）、配置修改前后值。
4. 审计日志与业务表**存储原文**，展示与导出时脱敏；姓名、身份证号、手机号等敏感信息在展示和导出时必须脱敏。
5. 审计日志保留天数可配置，默认 1 年；日志清理行为本身必须记录审计。
6. P0 为普通审计日志，P1 增强日志防篡改。

### 10.6 授权规则（离线授权）

1. 未授权进入 30 天试用模式，全功能可用。
2. 试用到期后进入 7 天宽限期，界面醒目提醒，宽限期内全功能可用。
3. 宽限期后锁定采集功能，仅允许查看和导出。
4. 支持离线授权：采集站生成机器指纹，客户将指纹提交厂商，厂商内部工具生成注册码/授权文件，采集站导入激活。
5. 机器指纹 = CPU 序列号 + 主板序列号 + 磁盘序列号 + MAC 组合；更换任一硬件即视为新指纹，需重新授权。
6. 授权绑定采集站硬件，一个注册码/授权文件仅限一台采集站使用。
7. 授权信息使用 SM4 加密存储。
8. 检测到时钟回拨后自动锁定。
9. 授权到期瞬间立即中断当前正在进行的采集任务。
10. 本期不支持在线激活。

### 10.7 数据权限规则（统一 RBAC）

1. 单机版与平台版统一采用 RBAC（账号-角色-权限点）机制，并支持数据权限与数据隔离；RBAC 主体为账号，账号可关联一个用户（人员），用于确定"本人数据"的数据范围。
2. 预置角色（双端一致）：
   - 管理员：全部权限；
   - 部门负责人：本部门数据操作；
   - 操作员：当前账号关联用户的数据操作（本人数据）；
   - 审计员：全局只读。
3. 管理员可创建自定义角色并勾选权限点；预置角色作为初始数据提供。
4. 数据范围按组织挂接：上级可见所有下级组织数据，下级不可见上级/平级数据，同级互相隔离。
5. 文件列表、预览、报警、统计、日志等所有功能模块均按数据范围过滤。

### 10.8 数据备份规则

1. 平台数据库：每日自动备份，保留份数可配置（建议默认 30 份），支持手动备份；备份动作留审计。
2. 采集站本地数据库（SQLite/Kingbase）：每日自动备份，保留最近 7 份。
3. 本地加密缓存为待上传中间态，不备份。

### 10.9 跨端 ID 与数据同步规则

1. 各端数据库内部主键采用本端自增 ID（代理键），仅用于本端内部关联，不跨端传输。
2. 跨端引用一律使用业务编号（自然键）：采集站编号、记录仪序列号、用户工号、部门编码全局唯一；文件业务编号 = `{采集站编号}-{本地文件ID}`。
3. 采集站本地文件元数据记录不物理删除（软删/保留），保证本地文件 ID 永不复用；采集站编号录入后不可变更（名称、位置等描述字段可改），避免自然键漂移。
4. 平台收到文件元数据上报后，以平台自增 `FileRecord.Id` 为主键，并建立唯一索引 `(StationId, LocalFileId)`；同一文件重复上报（断网补报、重试）按唯一索引幂等处理（更新或忽略），不产生重复记录。
5. 跨端通信契约只携带业务编号与本端 ID 的复合引用（如 `(StationCode, LocalFileId)`），不依赖任何一端自增主键；平台侧操作回引经平台 ID 解析后转发给对应采集站。
6. 采集站首次连接平台时按"采集站编号 + 机器指纹"注册，平台返回 `StationId`，采集站本地缓存；断网期间沿用缓存值，恢复后继续上报。
7. 通信契约只增不改不删（向后兼容）；破坏性变更必须走 API 版本化（`/api/v1` → `/api/v2`），允许两端不同步升级。

| 纳管规模 | 首版建议支持 50 台采集站、500 台记录仪 | 更大规模进入专项性能测试 |
| 时间基准 | 采集时间 = 采集站系统时间；记录仪原始时间单独存字段；检索默认按采集时间，支持按原始时间筛选 | 使用时间不一致的记录仪样例验证 |
| 传输安全 | P0 强制 HTTPS/TLS；TLCP 后续 | 内网访问、平台接口、单机 Web 局域网访问均需认证和加密 |
| 国密能力 | SM2 签名/验签、SM3 哈希、SM4 加密可用 | 覆盖文件校验、元数据签名、指令签名、缓存/凭据加密 |
| 可靠性 | 断网可继续本地采集和缓存；恢复后补推；单路异常不影响其他通道 | 通过断网、断开设备、存储失败等场景验证 |
| 隐私保护 | 展示、导出、日志均需脱敏 | 使用包含姓名、身份证号、手机号的样例数据验证 |
| 兼容性 | 支持指定操作系统、数据库（三库）和部署方式；x86_64 + ARM64 | 以客户确认的版本清单为准 |
| 备份恢复 | 平台每日备份+手动备份；采集站本地库每日备份 | 备份恢复演练通过 |

## 十五、主要风险

| 风险 | 影响 | 应对策略 |
| :--- | :--- | :--- |
| USB/MTP 跨平台兼容 | 可能影响记录仪识别、文件枚举、采集稳定性 | 尽早使用客户样机在 Windows、Ubuntu、麒麟、统信上验证 |
| 私有加密设备 SDK | SDK 转 UMS 行为、平台差异可能影响识别 | 尽早确认目标 SDK 清单并在客户样机上验证 |
| 国产系统权限与驱动差异 | 可能影响 USB、后台服务、自启动、文件权限 | 建立目标 OS 与 CPU 架构版本清单并做专项验证 |
| 三库双端适配 | MySQL/PostgreSQL/Kingbase 建表、迁移、分页、事务差异可能影响 ORM 与脚本 | 数据访问层抽象，三类数据库从首日并行适配，尽早引入 Kingbase 联调 |
| 信创 ARM64 | Avalonia 与原生依赖在 ARM64 麒麟/统信上的兼容性 | 目标架构清单化，提前在 ARM64 环境验证 UI 与 USB |
| 视频在线播放 | 受编码格式、封装、浏览器、带宽影响 | P0 限定常见执法记录仪视频格式，H.264 通过采集站代理转发预览；H.265 引导下载，转码 P2 |
| ini 绑定安全 | UMS 无法自动验证物理设备身份，ini 存在被复制/篡改风险 | SM3 校验 + 台账一致性比对；疑似篡改按未绑定处理并报警；P1 增加 MTP 序列号交叉验证 |
| 国密实现 | 密钥管理、证书、签名验签、算法库兼容存在风险 | 尽早确认算法库和密钥管理方案，先覆盖 P0 场景 |
| 授权机制 | 离线授权、机器指纹、时钟回拨涉及业务规则和安全策略 | 授权规则已冻结，按本文档 10.6 节实现和测试 |
| 断点续传/分片上传 | FTP/SFTP 协议差异影响续传正确性 | 选用成熟库（FluentFTP 等），按目标存储实测 |
| 并发采集性能 | 受 USB 总线、硬盘、网络、记录仪性能影响 | 验收以客户硬件为准，建立实测基线 |
| 部署环境差异 | Docker 与裸机、不同 OS、数据库和 CPU 架构组合复杂 | 形成标准部署矩阵和配置样例，优先验证客户目标组合 |
