## 一、快速入门

### 1.1 一句话概括

**采集站的所有加密动作（密码哈希、文件摘要、签名、加解密）都通过"策略 + 工厂 + 门面"三层路由，算法由管理员在设置页选择，无需改代码。**

### 1.2 五分钟记忆





| 你想做什么            | 用哪个门面                          | 底层算法             |
| :-------------------- | :---------------------------------- | :------------------- |
| 用户登录密码          | `IPasswordService`                  | PBKDF2-HMAC-SM3      |
| 授权文件加密+签名     | `LicenseService`（内部走策略）      | SM4-GCM + SM2-SM3    |
| FTP/SFTP 密码存储     | `CryptoExtensions`                  | SM4-GCM              |
| 文件内容加密          | `IFileEncryptionService`            | SM4-GCM（分块 STFE） |
| 文件摘要 + 元数据签名 | `IFileSigningService`               | SM3 + SM2-SM3        |
| 记录仪绑定 MAC        | `RecorderBindingFile`（内部走策略） | HMAC-SM3             |
| 平台上报签名          | `IReportingSigner`                  | SM2-SM3              |

**业务代码永远不直接调用算法接口**（`IPasswordHasher` / `ISigner` / `IEncryptor` / `IHasher` / `IMacProvider`），只依赖门面。

### 1.3 最小示例

csharp

```
// ❌ 错误：直接注入算法
public MyService(IPasswordHasher hasher) { ... }

// ✅ 正确：注入门面
public MyService(IPasswordService passwordService) { ... }

// 使用
var hash = await _passwordService.HashAsync("p@ssw0rd");
```

## 二、核心概念

### 2.1 五个算法接口





| 接口              | 目的         | 密钥            | 可逆 | 典型算法               |
| :---------------- | :----------- | :-------------- | :--- | :--------------------- |
| `IPasswordHasher` | 密码存储     | 无（盐公开）    | ❌    | PBKDF2-HMAC-SM3        |
| `IHasher`         | 内容指纹     | 无              | ❌    | SM3 / SHA-256          |
| `ISigner`         | 防伪签名     | 私钥签 / 公钥验 | ❌    | SM2-SM3 / RSA-SHA256   |
| `IEncryptor`      | 数据保密     | 对称密钥        | ✅    | SM4-GCM / AES-256-GCM  |
| `IMacProvider`    | 共享密钥认证 | 对称密钥        | ❌    | HMAC-SM3 / HMAC-SHA256 |

#### 三者区别速记





| 对比     | IHasher | ISigner          | IEncryptor     |
| :------- | :------ | :--------------- | :------------- |
| 谁能生成 | 任何人  | 只有私钥持有者   | 只有密钥持有者 |
| 谁能验证 | 任何人  | 任何人（用公钥） | 只有密钥持有者 |
| 能解密吗 | ❌       | ❌                | ✅              |
| 用途     | 完整性  | 真实性 + 完整性  | 机密性         |

### 2.2 三个"用途"概念





| 概念                | 说明               | 示例                           |
| :------------------ | :----------------- | :----------------------------- |
| **CryptoUsage**     | 用途标识（做什么） | `password` / `file_encryption` |
| **CryptoAlgorithm** | 算法标识（用什么） | `PBKDF2-HMAC-SM3` / `SM4-GCM`  |
| **CryptoPolicy**    | 用途 → 算法 的映射 | `password → PBKDF2-HMAC-SM3`   |

**一个用途对应一个算法**（组合算法用 `SecondaryAlgorithm` 表达，如 License 的"加密+签名"）。

## 四、加密策略

### 4.1 数据库表

**表**：`station_crypto_policy`





| 字段                 | 类型        | 说明                              |
| :------------------- | :---------- | :-------------------------------- |
| Id                   | bigint      | 主键                              |
| UsageCode            | varchar(32) | 用途标识                          |
| Algorithm            | varchar(64) | 主算法                            |
| SecondaryAlgorithm   | varchar(64) | 组合算法第二段（如 License 签名） |
| ParamsJson           | text        | 算法参数（默认走内置）            |
| LegacyAlgorithmsJson | text        | 迁移期允许回退的旧算法            |
| AllowLegacy          | bool        | 是否允许旧算法回退                |
| Enabled              | bool        | 是否启用                          |
| Source               | varchar(16) | "Local" / "Platform"              |
| UpdatedAt            | datetime    | 最后更新时间                      |
| UpdatedBy            | varchar(64) | 最后更新人                        |

### 4.2 七种用途





| UsageCode          | 默认算法          | 备选                     | 应用场景             |
| :----------------- | :---------------- | :----------------------- | :------------------- |
| `password`         | PBKDF2-HMAC-SM3   | MD5(兼容)、PBKDF2-SHA256 | 登录密码             |
| `license`          | SM4-GCM + SM2-SM3 | AES-GCM + RSA-SHA256     | 授权文件             |
| `file_sig`         | SM3 + SM2-SM3     | SHA-256 + RSA-SHA256     | 文件元数据签名       |
| `secret_field`     | SM4-GCM           | AES-256-GCM              | FTP/SFTP 密码字段    |
| `file_encryption`  | SM4-GCM           | AES-256-GCM              | 文件内容加密（分块） |
| `recorder_binding` | HMAC-SM3          | HMAC-SHA256              | 记录仪绑定 MAC       |
| `reporting`        | SM2-SM3           | RSA-SHA256               | 平台上报签名         |

### 4.3 策略切换

**前置条件**：

- `AllowLegacy=true` 时，业务代码会自动尝试旧算法，成功则惰性重哈希
- 不同用途切换效果不同：
  - `password`：用户下次登录自动迁移
  - `file_sig` / `secret_field` / `file_encryption`：**新数据用新算法，旧数据保留**
  - `license`：切换后旧授权文件失效（需重新授权）

**操作**：设置页 → `🔒 安全与加密` → 选择算法 → 保存

### 4.4 策略读取缓存

- `CryptoPolicyService` 内部用 `IMemoryCache` 缓存 30 分钟（滑动过期）
- 策略更新时主动清缓存
- 业务代码调用 `GetAsync` 命中缓存，**性能零开销**

## 五、密钥管理

### 5.1 两类密钥





| 类型                | 用途                                 | 存储                | 分发                 |
| :------------------ | :----------------------------------- | :------------------ | :------------------- |
| **主密钥**          | 加密数据库敏感字段、派生文件加密密钥 | 密钥文件 / 环境变量 | 不出机器             |
| **业务密钥（PEM）** | 授权签名、上报签名                   | 独立 PEM 文件       | 公钥可分发，私钥保密 |

### 5.2 主密钥文件

**位置**：

- Windows：`%ProgramData%\Station\keys\master.key`
- Linux：`/etc/station/keys/master.key`

**格式**：

json

```
{
  "current": 2,
  "keys": [
    { "version": 1, "key": "base64(32B)", "createdAt": "2025-01-15T08:00:00Z" },
    { "version": 2, "key": "base64(32B)", "createdAt": "2025-09-21T10:30:00Z" }
  ]
}
```

**环境变量覆盖**：`STATION_MASTER_KEY`（base64 编码的 32 字节密钥）

### 5.3 密钥派生（HKDF）

**场景**：从主密钥派生业务子密钥，避免"一个密钥用到处"。

**算法**：`HKDF-SM3`

**参数**：





| 参数   | 值                                        |
| :----- | :---------------------------------------- |
| IKM    | 主密钥（32B）                             |
| Salt   | null                                      |
| Info   | `"station:file-encryption:v1"` 等用途标识 |
| Length | 32B                                       |

**已定义的派生用途**：

- `station:file-encryption:v1` → 文件内容加密密钥
- `station:recorder-binding:v1` → Binding MAC 密钥

### 5.4 密钥轮换

**触发**：设置页 → `🔒 安全与加密` → `轮换主密钥`

**流程**：

1. 生成新版本密钥（v2），标记 `current=2`
2. 扫描所有 `IsEncrypted=1` 的配置字段
3. 用旧密钥解密 → 新密钥加密 → 更新
4. 写审计 `MasterKeyRotate`
5. 旧版本密钥保留（支持历史数据解密）

**影响**：

- 无需停机
- 无需重加密文件（文件头部已带版本号）

### 5.5 密钥版本路由

**密文格式**：`v{n}:base64(...)`

- 写入：用当前 `current` 版本加密
- 读取：按密文自己的版本号解密，**不管 current 是几**

**这就是新旧数据共存的关键**。

## 六、算法实现

### 6.1 IPasswordHasher（3 个实现）





| 实现                 | 算法            | 用途                   |
| :------------------- | :-------------- | :--------------------- |
| `Sm3Pbkdf2Hasher`    | PBKDF2-HMAC-SM3 | **默认**，国密首选     |
| `Pbkdf2Sha256Hasher` | PBKDF2-SHA256   | 非国密备选             |
| `Md5LegacyHasher`    | MD5             | **仅兼容读**，禁止新写 |

**存储格式**：`sm3$迭代次数$盐(Base64)$哈希(Base64)`

**关键设计**：

- **迭代数 10000**：故意慢，抗暴力破解
- **盐随机 16B**：防彩虹表
- **算法前缀**：换算法后可识别旧格式
- **NeedsRehash**：判断是否需要按新参数重哈希

### 6.2 IHasher（2 个实现）





| 实现           | 算法        | 输出           |
| :------------- | :---------- | :------------- |
| `Sm3Hasher`    | SM3（国密） | 32 字节 Base64 |
| `Sha256Hasher` | SHA-256     | 32 字节 Base64 |

**特点**：快、无盐、无密钥、同输入同输出。

**用途**：文件完整性校验、内容指纹、签名的输入。

### 6.3 ISigner（2 个实现）





| 实现              | 算法                | 说明                   |
| :---------------- | :------------------ | :--------------------- |
| `Sm2Sm3Signer`    | SM2 签名 + SM3 摘要 | **国密首选**，内置 SM3 |
| `RsaSha256Signer` | RSA 签名 + SHA-256  | 非国密备选             |

**重要澄清**：`Sm2Sm3Signer.Sign(data)` 传入的是**原始数据**，内部自动做 SM3 摘要。**不要先算摘要再传**（会双重哈希）。

### 6.4 IEncryptor（2 个实现）





| 实现              | 算法        | 密文格式                    |
| :---------------- | :---------- | :-------------------------- |
| `Sm4GcmEncryptor` | SM4-GCM     | `v{n}:base64(nonce∥ct∥tag)` |
| `AesGcmEncryptor` | AES-256-GCM | 同上                        |

**AAD（附加认证数据）**：绑定上下文的明文，如 `"storage.targets.ftpPassword"`，防止密文跨字段替换。

### 6.5 IMacProvider（2 个实现）





| 实现                 | 算法        | 输出   |
| :------------------- | :---------- | :----- |
| `HmacSm3Provider`    | HMAC-SM3    | Base64 |
| `HmacSha256Provider` | HMAC-SHA256 | Base64 |

**与 IHasher 的区别**：

- `IHasher` 无密钥，任何人能算
- `IMacProvider` 有密钥，只有持密钥者能算

**用途**：记录仪绑定文件 MAC。

### 6.6 算法工厂

`ICryptoProviderFactory` 是算法名的"字典"：

csharp

```
factory.GetPasswordHasher("PBKDF2-HMAC-SM3")  // → Sm3Pbkdf2Hasher
factory.GetSigner("SM2-SM3")                 // → Sm2Sm3Signer
factory.GetEncryptor("SM4-GCM")              // → Sm4GcmEncryptor
factory.GetHasher("SM3")                     // → Sm3Hasher
factory.GetMacProvider("HMAC-SM3")           // → HmacSm3Provider
```

## 九、运维指南

### 9.1 首次部署





| 步骤 | 操作                                                         |
| :--- | :----------------------------------------------------------- |
| 1    | 部署应用，首次启动自动生成 `master.key`                      |
| 2    | 检查 `station_crypto_policy` 表已自动 seed 7 行（每用途一行） |
| 3    | 部署 PEM 密钥：`license-public.pem` / `reporting-private.pem` |
| 4    | 检查密钥文件权限（Windows ACL / Linux 600）                  |
| 5    | 启动时自检自动跑，失败弹 `SelfCheckDialog`                   |

### 9.2 密钥轮换

**时机**：每年一次 / 安全事件后 / 人员变动后

**操作**：

1. 设置页 → `🔒 安全与加密` → `轮换主密钥`
2. 等待完成（有进度条）
3. 查看审计列表确认成功

**注意**：

- 轮换不需停机
- 旧版本密钥**不要删除**（历史数据解密依赖）

### 9.3 算法迁移

**密码迁移**（如 MD5 → SM3）：

1. 设置页 → 切换算法
2. 勾选 `允许旧算法回退`
3. 用户下次登录自动重哈希
4. 数周后统计迁移进度（见 `MigratePasswordsAsync`）
5. 迁移完成后可取消 `允许旧算法回退`

**文件摘要迁移**：

- 新文件用新算法
- 旧文件保留旧算法标识
- **不能批量迁移**（需要重新读原文件）

### 9.4 备份恢复

**必须备份**：

- `master.key` 密钥文件
- `station_crypto_policy` 表
- `station_sys_setting` 表
- PEM 私钥文件（如 `reporting-private.pem`）

**恢复顺序**：

1. 恢复密钥文件（否则所有密文无法解密）
2. 恢复数据库
3. 启动应用

### 9.5 平台版 vs 单机版





| 场景   | 策略来源                     | 本地可改             |
| :----- | :--------------------------- | :------------------- |
| 单机版 | 本地 `station_crypto_policy` | ✅                    |
| 平台版 | 平台下发覆盖本地             | ❌（`ReadOnly=true`） |

## 十、故障排查

### 10.1 常见错误





| 现象             | 可能原因                       | 排查                                        |
| :--------------- | :----------------------------- | :------------------------------------------ |
| 密码验证总是失败 | 算法不一致 / Legacy 列表缺算法 | 检查 `station_crypto_policy` 的 password 行 |
| 密文解密失败     | 主密钥丢失 / AAD 不匹配        | 检查 `master.key` 是否存在、AAD 规则        |
| 授权文件验签失败 | 公钥文件错 / 算法字段错        | 检查 `LicenseOptions.PublicKeyFile`         |
| 绑定文件验证失败 | 旧格式 / 主密钥变更            | 提示用户重新绑定                            |
| 主密钥轮换失败   | 磁盘空间 / 权限                | 查看审计的 `FailedCount`                    |

### 10.2 诊断方法

**查看日志**：

- 搜索 `Station.Infrastructure.Security` 类别的日志
- 加解密失败会记 ERROR
- 历史明文会记 WARN

**查看审计**：

- 设置页 → `🔒 安全与加密` → 最近安全变更审计
- 或查询 `station_audit_log` 表

**启动自检**：

- 失败时 `SelfCheckDialog` 显示具体检查项
- 6 项：数据库、策略表、主密钥文件、主密钥往返、SM2 公钥、存储目标

### 10.3 恢复方案

**主密钥丢失**：

- 若有备份 → 恢复 `master.key`
- 若无备份 → **已加密数据全部无法解密**，只能清库重建

**误改算法**：

- 若旧算法仍在 `LegacyAlgorithms` → 业务能恢复
- 否则 → 需要手工回滚策略表

**配置文件损坏**：

- `station_sys_setting` 表损坏 → 从备份恢复
- 或删除对应行 → 回落到 appsettings 种子

## 结束语

**核心设计思想回顾**：

1. **策略模式**：算法可配置，业务代码不硬编码
2. **依赖倒置**：Application 定义接口，Infrastructure 实现
3. **门面封装**：业务代码只依赖门面，不接触算法
4. **版本化**：密文/密钥带版本号，支持平滑演进
5. **惰性迁移**：旧数据不批量迁，用户使用时自然迁移
6. **审计完备**：所有关键操作记入 `station_audit_log`
