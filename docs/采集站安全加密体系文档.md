## 一、快速入门

### 1.1 一句话概括

**采集站的所有加密动作（密码哈希、文件摘要、签名、加解密）都通过"策略 + 注册表 + 门面"三层路由，算法由管理员在设置页选择，无需改代码。**

### 1.2 五分钟记忆

| 你想做什么            | 用哪个门面              | 底层算法                |
| :-------------------- | :---------------------- | :---------------------- |
| 用户登录密码          | `IPasswordService`      | PBKDF2-HMAC-SM3         |
| 授权文件加密+签名     | `ILicenseCryptoService` | SM2-SM3（只签名不加密） |
| FTP/SFTP 密码存储     | `CryptoExtensions`      | SM4-GCM                 |
| 文件内容加密          | `IFileCryptoService`    | SM4-GCM（分块 STFE）    |
| 文件摘要 + 元数据签名 | `IFileCryptoService`    | SM3 + SM2-SM3           |
| 记录仪绑定 MAC        | `BindingEngine`         | HMAC-SM3                |
| 平台上报签名          | `ILicenseCryptoService` | SM2-SM3                 |

**业务代码永远不直接调用算法接口**（`IPasswordHasher` / `ISigner` / `IEncryptor` / `IHasher` / `IMacProvider`），只依赖门面。

### 1.3 最小示例

```csharp
// ❌ 错误：直接注入算法
public MyService(IPasswordHasher hasher) { ... }

// ✅ 正确：注入门面
public MyService(IPasswordService passwordService) { ... }

// 使用
var hash = await _passwordService.HashAsync("p@ssw0rd");
```

## 二、核心概念

### 2.1 五个算法接口

| 接口              | 目的         | 密钥            | 可逆 | 典型算法               |
| :---------------- | :----------- | :-------------- | :--- | :--------------------- |
| `IPasswordHasher` | 密码存储     | 无（盐公开）    | ❌    | PBKDF2-HMAC-SM3        |
| `IHasher`         | 内容指纹     | 无              | ❌    | SM3 / SHA-256          |
| `ISigner`         | 防伪签名     | 私钥签 / 公钥验 | ❌    | SM2-SM3 / RSA-SHA256   |
| `IEncryptor`      | 数据保密     | 对称密钥        | ✅    | SM4-GCM / AES-256-GCM  |
| `IMacProvider`    | 共享密钥认证 | 对称密钥        | ❌    | HMAC-SM3 / HMAC-SHA256 |

### 2.2 三个"用途"概念

| 概念                | 说明               | 示例                           |
| :------------------ | :----------------- | :----------------------------- |
| **CryptoUsage**     | 用途标识（做什么） | `password` / `file_encryption` |
| **CryptoAlgorithm** | 算法标识（用什么） | `PBKDF2-HMAC-SM3` / `SM4-GCM`  |
| **CryptoPolicy**    | 用途 → 算法 的映射 | `password → PBKDF2-HMAC-SM3`   |

**一个用途对应一个算法**（组合算法用 `SecondaryAlgorithm` 表达，如 License 的"签名算法"）。

### 2.3 依赖倒置原则

```
Station.Crypto           ← 契约（接口、常量、DTO、异常）
    ↑
Station.Crypto.Engine    ← 算法实现 + 协议编排（授权、绑定、STFE、密钥）
    ↑
Station.Domain           ← 实体
Station.Application      ← 门面接口 + 策略模型
    ↑
Station.Infrastructure   ← 门面实现 + DI + 密钥管理
    ↑
Station.Desktop / Web    ← UI
```

**铁律**：

- `Station.Crypto` 零依赖（仅 `System.*`）
- `Station.Application` 永不引用 `Station.Crypto.Engine` / `Station.Infrastructure`
- `Station.Tools` 只引用 `Station.Crypto` + `Station.Crypto.Engine`，不引用 `Application` / `Infrastructure`

## 四、加密策略

### 4.1 数据库表

**表**：`station_crypto_policy`

| 字段                 | 类型        | 说明                                  |
| :------------------- | :---------- | :------------------------------------ |
| Id                   | bigint      | 主键                                  |
| UsageCode            | varchar(32) | 用途标识                              |
| Algorithm            | varchar(64) | 主算法                                |
| SecondaryAlgorithm   | varchar(64) | 组合算法第二段（如 License 签名算法） |
| ParamsJson           | text        | 算法参数（默认走内置）                |
| LegacyAlgorithmsJson | text        | 迁移期允许回退的旧算法                |
| AllowLegacy          | bool        | 是否允许旧算法回退                    |
| Enabled              | bool        | 是否启用                              |
| Source               | varchar(16) | "Local" / "Platform"                  |
| UpdatedAt            | datetime    | 最后更新时间                          |
| UpdatedBy            | varchar(64) | 最后更新人                            |

### 4.2 七种用途

| UsageCode          | 默认算法        | 备选                     | 应用场景                                     |
| :----------------- | :-------------- | :----------------------- | :------------------------------------------- |
| `password`         | PBKDF2-HMAC-SM3 | MD5(兼容)、PBKDF2-SHA256 | 登录密码                                     |
| `license`          | SM4-GCM         | AES-256-GCM              | 授权文件（当前只签名不加密）                 |
| `file_sig`         | SM3             | SHA-256                  | 文件元数据签名（SecondaryAlgorithm=SM2-SM3） |
| `secret_field`     | SM4-GCM         | AES-256-GCM              | FTP/SFTP 密码字段                            |
| `file_encryption`  | SM4-GCM         | AES-256-GCM              | 文件内容加密（分块）                         |
| `recorder_binding` | HMAC-SM3        | HMAC-SHA256              | 记录仪绑定 MAC                               |
| `reporting`        | SM2-SM3         | RSA-SHA256               | 平台上报签名                                 |

### 4.3 策略切换影响

| 用途       | 切换影响             | 旧数据                 |
| :--------- | :------------------- | :--------------------- |
| 登录密码   | 用户下次登录自动升级 | ✅ 可平滑迁移           |
| 敏感字段   | 新写入用新算法       | ✅ 旧密文保留           |
| 文件摘要   | 新文件用新算法       | ✅ 旧文件保留原算法标记 |
| 文件加密   | 新文件用新算法       | ✅ 旧文件保留           |
| 授权文件   | **旧授权需重新生成** | ⚠️ 需通知客户           |
| 记录仪绑定 | **旧绑定文件失效**   | ⚠️ 需重新绑定           |
| 平台上报   | 需平台同步切换       | ⚠️ 需协调               |

### 4.4 策略读取缓存

- `CryptoPolicyService` 内部用 `IMemoryCache` 缓存 30 分钟（滑动过期）
- 策略更新时主动清缓存
- 业务代码调用 `GetAsync` 命中缓存，**性能零开销**

## 五、密钥管理

### 5.1 两类密钥

| 类型                | 用途                                 | 存储                           | 分发                 |
| :------------------ | :----------------------------------- | :----------------------------- | :------------------- |
| **主密钥**          | 加密数据库敏感字段、派生文件加密密钥 | 密钥文件 / 环境变量 / 远程下发 | 不出机器             |
| **业务密钥（PEM）** | 授权签名、上报签名                   | 独立 PEM 文件                  | 公钥可分发，私钥保密 |

### 5.2 主密钥抽象

`IMasterKeyProvider` 是主密钥的统一契约：

```csharp
public interface IMasterKeyProvider
{
    int CurrentVersion { get; }
    IReadOnlyList<int> GetVersions();
    byte[] GetKey(int version);
    Task<int> RotateAsync(CancellationToken ct = default);
    byte[] DeriveBindingKey();
    byte[] DeriveFileEncryptionKey(int keyVersion);
}
```

| 实现                                        | 场景                 | 状态       |
| :------------------------------------------ | :------------------- | :--------- |
| `FileMasterKeyProvider`（Engine）           | 单机部署             | ✅ 已实现   |
| `RemoteMasterKeyProvider`（Infrastructure） | 集群部署（平台下发） | ⏳ 骨架就位 |

### 5.3 主密钥文件格式

**位置**：

- Windows：`%ProgramData%\Station\keys\master.key`
- Linux：`/etc/station/keys/master.key`

**格式**（持久化契约）：

```json
{
  "current": 2,
  "keys": [
    { "version": 1, "key": "base64(32B)", "createdAt": "2025-01-15T08:00:00Z" },
    { "version": 2, "key": "base64(32B)", "createdAt": "2025-09-21T10:30:00Z" }
  ]
}
```

**权限**：Windows 用 ACL 限当前账户；Linux `chmod 600`

**环境变量覆盖**：`STATION_MASTER_KEY`（base64 编码的 32 字节密钥）

### 5.4 密钥派生（HKDF）

**算法**：`HKDF-SM3`

**info 常量集中**（`Station.Crypto.HkdfInfo`）：

| 常量               | 值                               | 用途             |
| :----------------- | :------------------------------- | :--------------- |
| `FileEncryption`   | `"station:file-encryption:v1"`   | 文件内容加密密钥 |
| `RecorderBinding`  | `"station:recorder-binding:v1"`  | Binding MAC 密钥 |
| `LicenseSigning`   | `"station:license-signing:v1"`   | 授权签名（预留） |
| `ReportingSigning` | `"station:reporting-signing:v1"` | 上报签名（预留） |

**⚠️ 持久化契约**：一旦上线，info 字符串禁止修改。

### 5.5 密钥轮换

**触发**：设置页 → `🔒 安全与加密` → `轮换主密钥`

**流程**：

1. 生成新版本密钥（v2），标记 `current=2`
2. 扫描所有 `IsEncrypted=1` 的配置字段
3. 用旧密钥解密 → 新密钥加密 → 更新
4. 写审计 `MasterKeyRotate`
5. 旧版本密钥保留（支持历史数据解密）

**影响**：

- 无需停机
- 无需重加密文件（文件头部已带版本号）

### 5.6 密钥版本路由

**密文格式**：`v{n}:base64(...)`

- 写入：用当前 `current` 版本加密
- 读取：按密文自己的版本号解密，**不管 current 是几**

**这就是新旧数据共存的关键**。

### 5.7 主密钥线程安全

`FileMasterKeyProvider` 采用**无锁读 + 串行写**：

| 操作          | 策略                                                        |
| :------------ | :---------------------------------------------------------- |
| `GetKey`      | `Volatile.Read(ref _cache)` + 不可变 DTO 引用替换，**无锁** |
| `RotateAsync` | `SemaphoreSlim` 串行化 + **先落盘后更新内存**               |
| 环境变量      | `Lazy<byte[]?>` 一次性解析，激活时完全覆盖文件              |

## 六、算法实现

### 6.1 IPasswordHasher（3 个实现）

| 实现                 | 算法            | 用途                   |
| :------------------- | :-------------- | :--------------------- |
| `Sm3Pbkdf2Hasher`    | PBKDF2-HMAC-SM3 | **默认**，国密首选     |
| `Pbkdf2Sha256Hasher` | PBKDF2-SHA256   | 非国密备选             |
| `Md5LegacyHasher`    | MD5             | **仅兼容读**，禁止新写 |

**存储格式**：`sm3$迭代次数$盐(Base64)$哈希(Base64)`

### 6.2 IHasher（2 个实现）

| 实现           | 算法        | 输出           |
| :------------- | :---------- | :------------- |
| `Sm3Hasher`    | SM3（国密） | 32 字节 Base64 |
| `Sha256Hasher` | SHA-256     | 32 字节 Base64 |

### 6.3 ISigner（2 个实现）

| 实现              | 算法                | 说明                   |
| :---------------- | :------------------ | :--------------------- |
| `Sm2Sm3Signer`    | SM2 签名 + SM3 摘要 | **国密首选**，内置 SM3 |
| `RsaSha256Signer` | RSA 签名 + SHA-256  | 非国密备选             |

**重要澄清**：`Sm2Sm3Signer.Sign(data)` 传入的是**原始数据**，内部自动做 SM3 摘要。**不要先算摘要再传**（会双重哈希）。

### 6.4 IEncryptor（2 个实现）

| 实现              | 算法        | 密文格式                    |
| :---------------- | :---------- | :-------------------------- |
| `Sm4GcmEncryptor` | SM4-GCM     | `v{n}:base64(nonce∥ct∥tag)` |
| `AesGcmEncryptor` | AES-256-GCM | 同上                        |

**密钥约定**：

- SM4：16 字节（32 字节时取前 16）
- AES-256：**必须** 32 字节，长度不符抛 `CryptoException`

**AAD**：绑定上下文的明文，如 `"storage.targets.ftpPassword"`，防止密文跨字段替换。

### 6.5 IMacProvider（2 个实现）

| 实现                 | 算法        | 输出   |
| :------------------- | :---------- | :----- |
| `HmacSm3Provider`    | HMAC-SM3    | Base64 |
| `HmacSha256Provider` | HMAC-SHA256 | Base64 |

### 6.6 算法注册表（唯一 switch）

`AlgorithmRegistry` 是算法解析的唯一入口：

```csharp
AlgorithmRegistry.Default.GetPasswordHasher("PBKDF2-HMAC-SM3")
AlgorithmRegistry.Default.GetSigner("SM2-SM3")
AlgorithmRegistry.Default.GetEncryptor("SM4-GCM", keys)
AlgorithmRegistry.Default.GetHasher("SM3")
AlgorithmRegistry.Default.GetMacProvider("HMAC-SM3")
```

**收益**：新增算法只需改 1 处（`AlgorithmRegistry` + `CryptoAlgorithm`）。

### 6.7 STFE 文件格式

**格式**：

```
Header(32B) + Chunk0 + Chunk1 + ...
Header: Magic "STFE" | Ver | Algo | KeyVer | ChunkSize | NonceSeed | Reserved
Chunk:  Nonce(12) | Ciphertext(N) | Tag(16)
```

**Header 布局（小端）**：

| 偏移 | 长度 | 字段                             |
| :--- | :--- | :------------------------------- |
| 0    | 4    | Magic "STFE"                     |
| 4    | 1    | Version                          |
| 5    | 1    | AlgorithmId (0x01=SM4, 0x02=AES) |
| 6    | 4    | KeyVersion (int32 LE)            |
| 10   | 4    | ChunkSize (int32 LE)             |
| 14   | 8    | NonceSeed                        |
| 22   | 10   | Reserved（全 0）                 |

**参数**：

- ChunkSize = 4 MB（默认）
- 密钥版本写在 Header，支持轮换后读旧文件
- 每块独立 GCM 认证，单块损坏不影响其他块

### 6.8 三个关键正确性保证

| 项               | 保证                                                         |
| :--------------- | :----------------------------------------------------------- |
| **AES 密钥长度** | 长度不符（非 32 字节）抛异常，不再静默截断                   |
| **跨平台端序**   | 全部 `BinaryPrimitives.*LittleEndian`，与机器端序无关        |
| **流式解密**     | `StfeDecryptStream` 逐块解密，内存 O(chunkSize)，不落临时文件 |

### 6.9 并行分块

加密策略：批量读取 N 块 → `Parallel.For` 并行加密 → 顺序写入。

批次大小动态计算（目标 32 MB 批次，最多 16 块）。

**SM4 软件实现（BouncyCastle）单线程 ~150 MB/s，4 核并行 ~600 MB/s。**

### 6.10 流式解密 API

| API                                              | 用途                    | 内存                |
| :----------------------------------------------- | :---------------------- | :------------------ |
| `StfeDecryptStream.Open(path, keys)`             | 通用流式读（上传）      | O(chunkSize) = 4MB  |
| `StfeAsyncChunks.DecryptChunksAsync(path, keys)` | `IAsyncEnumerable` 管道 | O(80KB + chunkSize) |

**注意**：`StfeDecryptStream` 不支持 `Seek`（顺序流）。

## 七、协议编排（授权 / 绑定）

### 7.1 为什么需要"协议编排层"

授权文件生成逻辑在**两个地方**都要用：

- **Tools**：离线工具（内部授权签发）
- **Infrastructure**：采集站运行时（平台统一下发）

如果各写一份，格式易漂移。**协议编排层**（`LicenseEngine` / `BindingEngine`）把纯业务逻辑下沉到 `Station.Crypto.Engine`，Tools 和 App 都变成薄壳。

### 7.2 LicenseEngine

**位置**：`Station.Crypto.Engine/Licensing/LicenseEngine.cs`

**职责**：

- `Build(payload, privateKeyPem, signer)` → 授权文件 JSON
- `Validate(licenseJson, publicKeyPem, signerResolver, ...)` → 验签 + 业务校验
- `Inspect(licenseJson)` → 仅解析内容

**不负责**：策略解析、密钥读取、日志、文件 IO。

**授权文件是"只签名不加密"模式**：

```
payload → canonical JSON → 签名 → 组装 LicenseFile
```

| 字段                 | 说明                            |
| :------------------- | :------------------------------ |
| `Payload`            | canonical JSON 明文（非密文）   |
| `SignatureAlgorithm` | "SM2-SM3" / "RSA-SHA256"        |
| `Signature`          | 对 Payload 字节的签名（Base64） |

**为什么只签名不加密**：

- 授权内容（站点编号、指纹、到期时间）本身不是机密
- 签名足以防伪、防篡改
- 采集站只需公钥即可验证，无需与签发方共享主密钥

### 7.3 BindingEngine

**位置**：`Station.Crypto.Engine/Binding/BindingEngine.cs`

**职责**：

- `Build(info, bindingKey, macProvider)` → INI 内容
- `Validate(content, bindingKey, macResolver)` → 验证 MAC
- `Inspect(content)` → 仅解析内容

**绑定文件格式（ini）**：

```ini
[binding]
recorder_serial=SN123
recorder_model=MODEL-A
user_no=U001
user_name=张三
dept_code=D01
dept_name=技术部
bound_at=2026-09-22T10:30:00.0000000+08:00
mac_algo=HMAC-SM3
mac=base64...
```

**MAC 签名串**：`serial|model|userNo|userName|deptCode|deptName|boundAt`

### 7.4 调用方差异（合理差异）

| 调用方         | 如何拿 signer / macProvider                     |
| :------------- | :---------------------------------------------- |
| Tools          | `AlgorithmRegistry.Default.GetSigner(参数算法)` |
| Infrastructure | `await policy.GetSignerAsync(usageCode, ct)`    |

**业务逻辑共享，算法来源由调用方决定** —— 这就是协议编排层的价值。

## 八、业务场景

### 8.1 用户登录密码

**注册/重置**：

```csharp
var hash = await _passwordService.HashAsync("p@ssw0rd");
// 存 hash 到 user.password_hash
```

**登录**：

```csharp
var result = await _passwordService.VerifyAsync(inputPwd, user.PasswordHash);
if (result.Ok)
{
    if (result.NeedsRehash)
    {
        // 惰性重哈希（旧算法或参数升级）
        user.PasswordHash = await _passwordService.HashAsync(inputPwd);
        await _userRepo.UpdateAsync(user);
    }
    // 登录成功
}
```

**迁移机制**：

- `AllowLegacy=true` 时，验证失败后按 `LegacyAlgorithms` 列表回退
- 命中旧算法 → 立即用新算法重哈希
- 用户无感知，数天到数周内自然迁移完

### 8.2 授权文件

**生成**（内部工具或管理平台）：

1. 构造 canonical JSON payload
2. 用私钥签名（SM2-SM3）
3. 序列化为授权文件 JSON

**验证**（采集站）：

1. 解析文件结构
2. 按文件内 `SignatureAlgorithm` 字段选算法
3. 验签（公钥）
4. 业务校验：站点编号、硬件指纹、到期时间

**注意**：当前采用"只签名不加密"模式，无需解密步骤。

### 8.3 FTP/SFTP 密码存储

```csharp
// 保存
var cipher = await policy.ProtectSecretAsync(
    group: "storage.targets", key: "ftpPassword", plainPassword);

// 读取
var plain = await policy.TryUnprotectSecretAsync(
    group: "storage.targets", key: "ftpPassword", cipher);
```

**AAD 约定**：`"{group}.{key}"`，如 `"storage.targets.ftpPassword"`

### 8.4 文件内容加密（STFE 分块）

**触发**：采集完成、写入本地缓存后。

**加密流程**：

```
采集完成
  ├─ 算明文 SM3 摘要
  ├─ 构造元数据 + SM2 签名
  ├─ 加密文件（STFE 并行分块）
  └─ 写 DB：ContentDigest / DigestAlgorithm / Signature
```

**上传流程**：

```
上传时读取 RemoteContentMode 配置
  ├─ Plaintext 模式：解密流上传（OpenDecryptStream）
  └─ Ciphertext 模式：直接上传密文文件
```

### 8.5 文件摘要 + 元数据签名

**摘要**：明文的 SM3（采集时算）
**签名**：对元数据包签名（不是对文件本身）

**元数据 canonical JSON**：

```json
{
  "fileNo": "ST0001-12345",
  "fileName": "video.mp4",
  "size": 104857600,
  "contentDigest": "base64...",
  "digestAlgorithm": "SM3",
  "collectedAt": "2026-09-22T10:30:00Z",
  "stationCode": "ST0001"
}
```

**签名对象**是这段 JSON 的字节（SM2Signer 内部含 SM3）。

### 8.6 记录仪绑定 MAC

**目的**：防止 `station_bind.ini` 被伪造/篡改。

**算法**：HMAC-SM3（对称 MAC，不用非对称签名）

**密钥**：从主密钥 HKDF 派生（`HkdfInfo.RecorderBinding`）

### 8.7 平台上报签名

**场景**：报警状态、授权状态上报给平台。

**流程**：

1. 构造 canonical JSON 载荷
2. SM2 私钥签名
3. 上报时带签名
4. 平台用公钥验签

**私钥文件**：`keys/reporting-private.pem`（`ReportingOptions.PrivateKeyFile`）

## 十、运维指南

### 10.1 首次部署

| 步骤 | 操作                                                         |
| :--- | :----------------------------------------------------------- |
| 1    | 部署应用，首次启动自动生成 `master.key`                      |
| 2    | 检查 `station_crypto_policy` 表已自动 seed 7 行              |
| 3    | 部署 PEM 密钥：`license-public.pem` / `reporting-private.pem` |
| 4    | 检查密钥文件权限（Windows ACL / Linux 600）                  |
| 5    | 启动自检（失败弹 `SelfCheckDialog`）                         |

### 10.2 密钥轮换

**时机**：每年一次 / 安全事件后 / 人员变动后

**操作**：

1. 设置页 → `🔒 安全与加密` → `轮换主密钥`
2. 等待完成（有进度条）
3. 查看审计列表确认成功

**注意**：

- 轮换不需停机
- 旧版本密钥**不要删除**（历史数据解密依赖）

### 10.3 算法迁移

**密码迁移**（如 MD5 → SM3）：

1. 设置页 → 切换算法
2. 勾选 `允许旧算法回退`
3. 用户下次登录自动重哈希
4. 数周后统计迁移进度
5. 迁移完成后可取消 `允许旧算法回退`

**文件摘要迁移**：

- 新文件用新算法
- 旧文件保留旧算法标识
- **不能批量迁移**（需要重新读原文件）

### 10.4 备份恢复

**必须备份**：

- `master.key` 密钥文件
- `station_crypto_policy` 表
- `station_sys_setting` 表
- PEM 私钥文件（如 `reporting-private.pem`）

**恢复顺序**：

1. 恢复密钥文件（否则所有密文无法解密）
2. 恢复数据库
3. 启动应用

### 10.5 集群模式（预留）

**当前状态**：`FileMasterKeyProvider`（单机版）

**未来方案**（`RemoteMasterKeyProvider` 骨架已就位）：

```
主密钥（KEK，Key Encryption Key）
  ├─ 由管理平台生成
  ├─ 每客户一份（客户隔离）
  ├─ 通过平台下发到该客户的所有采集站
  └─ 本地加密缓存（用节点硬件指纹派生密钥包裹）

数据密钥（DEK，Data Encryption Key）
  ├─ 每客户一份
  ├─ 用 KEK 包裹后存本地
  └─ 实际用于加密敏感字段 / 文件
```

**启用方式**：`appsettings.json` 中 `CryptoOptions.Mode = "Remote"`。

## 十一、故障排查

### 11.1 常见错误

| 现象               | 可能原因                       | 排查                                            |
| :----------------- | :----------------------------- | :---------------------------------------------- |
| 密码验证总是失败   | 算法不一致 / Legacy 列表缺算法 | 检查 `station_crypto_policy` 的 password 行     |
| 密文解密失败       | 主密钥丢失 / AAD 不匹配        | 检查 `master.key` 是否存在、AAD 规则            |
| 授权文件验签失败   | 公钥文件错 / 算法字段错        | 检查 `LicenseOptions.PublicKeyFile`             |
| 绑定文件验证失败   | 旧格式 / 主密钥变更            | 提示用户重新绑定                                |
| 主密钥轮换失败     | 磁盘空间 / 权限                | 查看审计的 `FailedCount`                        |
| AES 加密报错       | 密钥长度非 32 字节             | 检查调用方传入的密钥                            |
| STFE 流不支持 Seek | 使用了 `StfeDecryptStream`     | 改用 `StfeFileEncryptor.DecryptAsync`（一次性） |

### 11.2 诊断方法

**查看日志**：

- 搜索 `Station.Infrastructure.Security` 类别的日志
- 加解密失败会记 ERROR
- 历史明文会记 WARN

**查看审计**：

- 设置页 → `🔒 安全与加密` → 最近安全变更审计
- 或查询 `station_audit_log` 表

**启动自检**：

- 失败时 `SelfCheckDialog` 显示具体检查项
- 6 项：数据库、策略表、主密钥文件、主密钥往返、SM2 公钥、存储目标

### 11.3 恢复方案

**主密钥丢失**：

- 若有备份 → 恢复 `master.key`
- 若无备份 → **已加密数据全部无法解密**，只能清库重建

**误改算法**：

- 若旧算法仍在 `LegacyAlgorithms` → 业务能恢复
- 否则 → 需要手工回滚策略表

**配置文件损坏**：

- `station_sys_setting` 表损坏 → 从备份恢复
- 或删除对应行 → 回落到 appsettings 种子

## 结束语

**核心设计思想回顾**：

1. **契约分层**：`Station.Crypto` 零依赖，所有层共用
2. **依赖倒置**：Application 定义接口，Infrastructure 实现
3. **协议编排下沉**：授权/绑定唯一实现在 Engine，Tools 和 App 天然兼容
4. **算法注册表**：唯一 switch，新增算法只改一处
5. **版本化**：密文/密钥带版本号，支持平滑演进
6. **惰性迁移**：旧数据不批量迁，用户使用时自然迁移
7. **流式解密**：大文件不落临时文件，内存 O(chunkSize)
8. **无锁读**：主密钥读路径无锁，写路径串行化 + 崩溃一致性
