## 一、环境要求

| 项 | 要求 |
|---|---|
| 桌面端 CPU | x86_64（海光/兆芯等）、ARM64（飞腾/鲲鹏等）；龙芯（loongarch64）暂不支持 |
| 桌面端 OS | Windows 10/11 x64；麒麟 / 统信 UOS（Linux x86_64 / arm64），需 Avalonia 依赖库（libX11、libxcb、fontconfig 等，信创发行版一般自带） |
| 平台服务器 | Linux x86_64 / arm64（Docker 20.10+ / Compose v2，推荐）；Windows Server 2019/2022 x64 裸机 |
| 数据库 | MySQL 8.0 / PostgreSQL 16 / Kingbase V8R6（三库配置切换，业务层自动建表播种） |
| 磁盘/内存建议 | 桌面端：可用磁盘 ≥ 20GB、内存 ≥ 4GB；平台：可用磁盘 ≥ 40GB、内存 ≥ 8GB（视在线站数与采集量） |
| 浏览器 | Chrome/Edge 90+（平台前端） |
| 协议 | USB Mass Storage（UMS）、MTP（P1）、私有加密 SDK（转 U 盘模式） |

**端口约定**：

| 组件 | 端口 | 说明 |
| :--- | :--- | :--- |
| 桌面端内置 Web | 5000 | 单机版界面（默认仅本机，可配置局域网访问） |
| 平台 API | 5100 | Docker（`PLATFORM_HTTP_PORT` 映射）或 Windows 裸机监听 |

## 二、部署拓扑

- **单机版**：桌面端独立运行（内置 Web 服务端口 5000，本地台账/授权/采集），不上报平台；
- **平台版**：桌面端注册到平台（`Station:Platform:Enabled=true` + BaseUrl + StationCode），文件元数据/报警/授权状态上报，指令/配置由平台下发；
- 平台版运行期间本地数据与配置**只读**，修改需到平台；从平台切回单机版可"继续用本地数据"或"清空恢复"。

## 三、安装前环境检测

> 目的：确认系统版本/架构/权限/资源满足要求，提前发现端口占用与依赖缺失，避免装到一半失败。

### 3.1 Windows（桌面端、平台 Windows 裸机）

管理员 PowerShell 逐段执行：

```powershell
# 1) 系统版本与架构 # AMD64 / ARM64
(Get-CimInstance Win32_OperatingSystem) | Select-Object Caption, Version, OSArchitecture
$env:PROCESSOR_ARCHITECTURE

# 2) 是否管理员（安装 MSI / 注册服务需要）
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole(
    [Security.Principal.WindowsBuiltInRole]::Administrator)

# 3) 磁盘与内存
Get-PSDrive C | Select-Object @{n='FreeGB';e={[math]::Round($_.Free/1GB,1)}},
    @{n='UsedGB';e={[math]::Round($_.Used/1GB,1)}}
[math]::Round((Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory/1GB,1)

# 4) 端口占用（桌面端 5000 / 平台 5100；被占用则先处理）
Get-NetTCPConnection -LocalPort 5000,5100 -ErrorAction SilentlyContinue |
    Select-Object LocalPort, State, OwningProcess

# 5) .NET 运行时（仅"框架依赖发布"需要；自包含可跳过）
dotnet --list-runtimes
```

### 3.2 Linux（桌面端、平台 Docker 主机）

```bash
# 1) 发行版与架构
cat /etc/os-release | head -3
uname -m                                  # x86_64 / aarch64

# 2) 当前用户权限（安装/写系统目录需要 sudo 或 root；输出 0 为 root）
id -u

# 3) 磁盘与内存
df -h /
free -h

# 4) Docker 与 Compose（平台 Docker 方式必需；无输出则按 5.1 安装）
docker --version && docker compose version

# 5) 桌面端图形依赖（缺失则按 4.4 安装）
ldconfig -p | grep -E 'libX11|libxcb|libxkbcommon|libfontconfig' | head -20 || echo "缺少桌面图形依赖"

# 6) 端口占用（桌面端 5000 / 平台 5100）
ss -tlnp | grep -E ':5000|:5100' || echo "端口空闲"
```

### 3.3 网络与防火墙

- 桌面端访问平台：采集站能连通平台 `5100`（或 HTTPS 端口）即可，无需入站放行 5000（除非要局域网访问单机版界面）；
- 平台入站：客户浏览器/采集站访问需放行 `5100`（或反向代理端口），放行命令见 5.4 / 6.5；
- 平台裸机连数据库：目标库端口（3306/5432/54321）需在数据库侧放行，连接串中主机名/地址要可达。

## 四、桌面端安装部署

### 4.1 方式一：Windows 安装包（MSI）

产物：`publish/packages/Station.Desktop-<version>-win-x64.msi`（CI 打标签自动生成，或本地
`powershell -File scripts/package-windows.ps1 -Version <version>`）。

```powershell
# 图形向导安装
msiexec /i Station.Desktop-0.1.0-win-x64.msi

# 静默安装（带日志，便于排查）
msiexec /i Station.Desktop-0.1.0-win-x64.msi /qn /l*v install.log

# 验证安装
Get-Service -ErrorAction SilentlyContinue                        # 桌面端不是服务，直接查目录
Test-Path "C:\Program Files\Station Desktop\Station.Desktop.UI.exe"

# 升级：直接运行新版 MSI（MajorUpgrade 覆盖安装，appsettings.json 不进包、不会被覆盖）
msiexec /i Station.Desktop-0.2.0-win-x64.msi /qn

# 卸载
msiexec /x Station.Desktop-0.1.0-win-x64.msi
```

要点：
- 安装位置 `C:\Program Files\Station Desktop\`，开始菜单有快捷方式；
- **运行账户须对安装/工作目录可写**：`station.db` 与采集文件写在进程工作目录（默认即安装目录），
  请用有写权限的账户运行（如管理员或专用账户）；
- 配置：安装目录下新建/修改 `appsettings.json`（见 4.5）。

### 4.2 方式二：Linux 安装包（DEB）

产物：`publish/packages/station-desktop_<version>_amd64.deb`（x86_64）/
`station-desktop_<version>_arm64.deb`（ARM64）。

```bash
# 安装（apt 会自动处理依赖；麒麟/UOS 同为 apt 系）
sudo apt-get update
sudo apt-get install -y ./station-desktop_0.1.0_amd64.deb        # x86_64；ARM64 用 _arm64.deb

# 验证
ls -l /usr/lib/station-desktop/Station.Desktop.UI
/usr/bin/station-desktop --version 2>/dev/null || echo "已安装（GUI 程序用桌面菜单启动）"

# 升级
sudo apt-get install -y ./station-desktop_0.2.0_amd64.deb         # appsettings.json 为 conffile，升级保留

# 卸载
sudo apt-get remove station-desktop
```

要点：
- 程序装在 `/usr/lib/station-desktop/`，`/usr/bin/station-desktop` 为软链，桌面菜单自动生成；
- 配置：`/usr/lib/station-desktop/appsettings.json`（conffile，升级不覆盖）；
- 若目标机无桌面（纯命令行），桌面端不可用，需图形界面。

### 4.3 方式三：拷贝部署（绿色版）

适用于无安装包或需要自定义目录的现场：

```powershell
# 开发/构建机发布三平台产物
powershell -File scripts/publish-desktop.ps1
# 产物：publish/desktop/win-x64 | linux-x64 | linux-arm64
```

```powershell
# Windows 目标机：整目录拷贝，建议固定到无空格目录
Copy-Item -Path .\publish\desktop\win-x64\* -Destination C:\Station\Desktop -Recurse -Force
```

```bash
# Linux 目标机
sudo mkdir -p /opt/station-desktop
sudo cp -r publish/desktop/linux-x64/* /opt/station-desktop/
sudo chmod +x /opt/station-desktop/Station.Desktop.UI
```

启动：Windows 双击 `Station.Desktop.UI.exe`；Linux `./Station.Desktop.UI`（需图形界面）。

### 4.4 Linux 依赖与中文字体（缺失安装）

自包含发布**无需 .NET 运行时**；仅需系统图形库与中文字体：

```bash
# Debian/Ubuntu/麒麟/UOS（apt 系）
sudo apt-get update
sudo apt-get install -y libx11-6 libxcb1 libxkbcommon0 libfontconfig1 libxrandr2 libxcursor1 libxi6 libice6 libsm6 libgl1
sudo apt-get install -y fonts-wqy-microhei        # 中文界面/PDF 导出

# CentOS/RHEL/麒麟服务器版（dnf 系）
sudo dnf install -y libX11 libxcb libxkbcommon fontconfig liberation-fonts
```

Windows 侧：默认自包含，**无需安装任何运行时**；若为框架依赖发布，需安装 .NET 8 Desktop Runtime。

### 4.5 配置文件（appsettings.json 关键项）

安装/拷贝完成后，按现场修改（文件不存在则新建，应用按默认值运行）：

```json
{
  "Station": {
    "Collect": { "SourceMode": "ums" },
    "Storage": { "Target": "Local", "LocalRoot": "", "StationNo": "ST0001" },
    "Platform": { "Enabled": false, "BaseUrl": "http://<平台IP>:5100", "StationCode": "ST0001" },
    "Command": { "PublicKeyPem": "", "Required": false }
  }
}
```

- 采集源：`Station:Collect:SourceMode`（`simulated` 开发 / `ums` 真机，插 U 盘后自动识别）；
- 存储：`Station:Storage:Target`（Local/Ftp/Sftp）、SFTP 主机/端口/账号/SftpRoot；
- 平台模式：`Station:Platform:Enabled=true`、`BaseUrl`、`StationCode`；
- 指令验签：`Station:Command:PublicKeyPem`（平台公钥）+ `Required=true`；
- 授权：启动后界面可见授权状态，试用 N 天或激活正式授权（见第八章）。

### 4.6 数据库说明

- **默认 SQLite**：零安装、零配置，首次启动自动在进程工作目录创建 `station.db`（WAL 模式）；
- **可选金仓**：`Station:Db:Provider=Kingbase` + `ConnectionString`（连接串见 7.4），
  采集站需能连通金仓端口，建表由应用自动完成；
- 备份：SQLite 文件整体拷贝即可（见第十章）。

### 4.7 开机自启

Windows（推荐任务计划，随登录启动）：

```powershell
schtasks /Create /TN "StationDesktop" /TR "C:\Program Files\Station Desktop\Station.Desktop.UI.exe" /SC ONLOGON /RL LIMITED /F
```

Linux（桌面环境自动启动）：

```bash
mkdir -p ~/.config/autostart
cp /usr/share/applications/station-desktop.desktop ~/.config/autostart/
```

### 4.8 启动验证

- 打开桌面界面，确认授权状态与采集源识别（模拟源/真机 U 盘）；
- 单机版内置 Web：本机访问 `http://127.0.0.1:5000`；
- 平台版：确认 `Station:Platform:Enabled=true` 后，平台台账能看到该站上线（心跳默认 5 分钟超时）。

> **内网/无网络现场**：桌面端自包含、安装运行无需联网；安装包与授权文件提前拷贝到目标机即可，
> 离线步骤见分册 04-1（Windows）/ 04-2（Linux）。

## 五、平台部署（Linux / Docker Compose，推荐）

### 5.1 Docker 与 Compose 安装（缺失安装）

```bash
# Ubuntu/Debian
sudo apt-get update
sudo apt-get install -y ca-certificates curl
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER          # 重新登录或执行 newgrp docker 后生效
newgrp docker

# Compose v2 插件
sudo apt-get install -y docker-compose-plugin
docker compose version
```

麒麟/UOS（无外网或 apt 源无 docker 时）：

```bash
# 方式 A：官方脚本（需外网）
curl -fsSL https://get.docker.com | sudo sh
# 方式 B：离线安装 .deb（在联网同架构机器下载 docker-ce/containerd.io/docker-ce-cli/docker-compose-plugin 四个包）
sudo dpkg -i docker-ce_*.deb containerd.io_*.deb docker-ce-cli_*.deb docker-compose-plugin_*.deb
sudo systemctl enable --now docker
```

国内环境可选镜像加速：`/etc/docker/daemon.json` 配置 `registry-mirrors` 后
`sudo systemctl restart docker`。

### 5.2 交付物与 .env 配置

交付包：`deploy/platform/`（Dockerfile + 三套 Compose + `.env.example`），需完整拷贝到服务器。

```bash
cd deploy/platform
cp .env.example .env
vi .env     # 至少修改以下项
```

| 变量 | 必填 | 说明 |
| :--- | :--- | :--- |
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` | 是（MySQL 方式） | 数据库 root/业务账号密码，生产必须改 |
| `PG_PASSWORD` | 是（PostgreSQL 方式） | 业务账号密码 |
| `ADMIN_PASSWORD` | 是 | 平台默认管理员密码（默认 `Admin@123`，**生产必须改**） |
| `PLATFORM_COMMAND_PRIVATE_KEY` | 是 | 平台指令 SM2 私钥（不配则指令以 unsigned 开发模式下发） |
| `PLATFORM_REPORTING_PUBLIC_KEY` | 是 | 采集站上报验签公钥（不配则上报跳过验签） |
| `PLATFORM_HTTP_PORT` | 否 | 宿主机映射端口，默认 5100 |
| `BACKUP_RETENTION` | 否 | 平台库每日自动备份保留份数，默认 30 |
| `KINGBASE_CONNECTION` | 金仓方式必填 | 外部金仓连接串（`Host=...;Port=54321;Database=station_platform;Username=...;Password=...`） |

### 5.3 启动 / 停止 / 查看

```bash
cd deploy/platform

# MySQL（默认）
docker compose -f docker-compose.yml --env-file .env up -d
# PostgreSQL
docker compose -f docker-compose.pg.yml --env-file .env up -d
# Kingbase（外部金仓）
docker compose -f docker-compose.kingbase.yml --env-file .env up -d

# 查看状态 / 日志 / 健康检查
docker compose -f docker-compose.yml --env-file .env ps
docker compose -f docker-compose.yml --env-file .env logs -f api
curl http://127.0.0.1:5100/api/v1/health

# 停止（保留数据卷与镜像）
docker compose -f docker-compose.yml --env-file .env down
```

- 首次启动自动建库建表并播种默认管理员，访问 `http://<主机>:5100`；
- 三库切换只改 `STATION__DB__PROVIDER` 与连接串（Compose 已固化，换文件即可）；
- 升级：停服 → 备份数据库（第十章）→ `docker compose ... build` → `up -d`。

### 5.4 HTTPS

- **方案 A（推荐）**：前置 Nginx/Caddy 反向代理终结 TLS，转发 `http://127.0.0.1:5100`；

  ```nginx
  server {
      listen 443 ssl;
      server_name platform.example.com;
      ssl_certificate     /etc/nginx/certs/server.crt;
      ssl_certificate_key /etc/nginx/certs/server.key;
      location / {
          proxy_pass http://127.0.0.1:5100;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
      }
  }
  ```

- **方案 B**：Kestrel 直接挂证书（pfx），Compose 的 api 服务追加环境变量与证书卷（见 deploy/platform/README.md）。

### 5.5 安全密钥

- `PLATFORM_COMMAND_PRIVATE_KEY`：平台指令 SM2 私钥（指令签名，采集站内置对应公钥）；不配则开发模式；
- `PLATFORM_REPORTING_PUBLIC_KEY`：采集站上报验签公钥；不配则上报跳过验签；
- 密钥由内部工具生成（SM2 密钥对）：私钥给平台、公钥内置到采集站；只进 `.env`，不入库。

### 5.6 离线交付

```bash
# 构建机（有网）：构建并导出镜像
cd deploy/platform
docker compose -f docker-compose.yml build
docker save station-platform-api:0.1.0 | gzip > station-platform-api-0.1.0.tar.gz
docker save mysql:8.0 | gzip > mysql-8.0.tar.gz                  # 按实际使用的库镜像导出

# 目标机（无网）：导入镜像后按 5.2/5.3 启动
docker load < station-platform-api-0.1.0.tar.gz
docker load < mysql-8.0.tar.gz
```

> 数据库若不在目标机（如金仓模式），可不导入库镜像，改用 `docker-compose.kingbase.yml` 连外部库。

## 六、平台部署（Windows 服务器裸机）

适用：Windows Server 2019/2022 x64、客户环境无 Docker 或明确指定 Windows。平台为 ASP.NET Core 8，
前端已随 `wwwroot` 一起发布，**无需额外 Web 服务器**。

### 6.1 发布产物

```powershell
# 自包含（目标机无需 .NET，推荐）
dotnet publish .\src\Station.Platform\Station.Platform.Api -c Release -r win-x64 --self-contained true -o .\publish\platform-api-win

# 或框架依赖（目标机需安装 .NET 8 Hosting Bundle）
dotnet publish .\src\Station.Platform\Station.Platform.Api -c Release -o .\publish\platform-api-fdd
```

将产物整目录拷贝到目标机（建议 `C:\platform\`，避免路径含空格），目录含
`Station.Platform.Api.exe`（自包含）与 `wwwroot/`（前端静态资源）。

### 6.2 配置

`appsettings.json` 或环境变量（环境变量优先级更高）：

| 变量 | 说明 |
| :--- | :--- |
| `STATION__DB__PROVIDER` | `MySql` / `PostgreSQL` / `Kingbase` |
| `STATION__DB__CONNECTIONSTRING` | 对应连接串（见 7.4） |
| `PLATFORM_COMMAND_PRIVATE_KEY` | 平台指令 SM2 私钥（生产必配） |
| `PLATFORM_REPORTING_PUBLIC_KEY` | 采集站上报验签公钥（生产必配） |
| `ASPNETCORE_URLS` | 如 `http://+:5100` 或 `https://+:8443` |

首次启动自动建库建表并播种默认管理员（`admin/Admin@123`，**生产必须改**）。

### 6.3 前台验证

```powershell
cd C:\platform
# 自包含
.\Station.Platform.Api.exe --urls http://127.0.0.1:5100
# 框架依赖
dotnet Station.Platform.Api.dll --urls http://127.0.0.1:5100

# 另开窗口验证
curl.exe http://127.0.0.1:5100/api/v1/health
curl.exe http://127.0.0.1:5100/        # 应返回平台首页（Vue 入口）
```

### 6.4 注册 Windows 服务（推荐）

```powershell
# 方式 A：sc.exe（系统自带）
sc.exe create StationPlatformApi binPath= "C:\platform\Station.Platform.Api.exe" start= auto
sc.exe config StationPlatformApi obj= ".\svc_station" password= "***"   # 可选：专用服务账号
sc.exe start StationPlatformApi
sc.exe query StationPlatformApi

# 方式 B：NSSM（更省心，日志重定向方便；nssm 需单独下载）
nssm install StationPlatformApi "C:\platform\Station.Platform.Api.exe"
nssm set StationPlatformApi AppDirectory "C:\platform"
nssm set StationPlatformApi AppStdout "C:\platform\logs\out.log"
nssm set StationPlatformApi AppStderr "C:\platform\logs\err.log"
nssm start StationPlatformApi
```

- 框架依赖发布时 `binPath` 指向 `dotnet.exe` 托管 dll（`sc` 引号内不能嵌套引号，用 NSSM 更省心）；
- 服务账号需对产物目录有读写权限（日志、备份写盘）。

### 6.5 防火墙放行

```powershell
netsh advfirewall firewall add rule name="Station Platform API 5100" dir=in action=allow protocol=TCP localport=5100
# 若用 HTTPS 8443：localport=8443 再执行一次
```

### 6.6 HTTPS

- 方案 A（推荐）：IIS 反向代理（ARR + URL Rewrite）终结 TLS，转发到 `http://127.0.0.1:5100`；
- 方案 B：Kestrel 直接挂证书（pfx），配置 `ASPNETCORE_Kestrel__Certificates__Default__Path` / `__Password`，
  URL 用 `https://+:8443`。

### 6.7 中文 PDF 导出

指向 TTF/OTF/TTC 字体文件。Linux 裸机需装 `fonts-wqy-microhei` 或配置 `STATION__EXPORT__FONTFILE`。

### 6.8 数据库

MySQL 8 / PostgreSQL 装 Windows 版、金仓装 Windows 服务端（安装与初始化见第七章）；三库切换只改
`PROVIDER` 与连接串，业务代码与建表自动适配。

## 七、数据库安装与初始化

> 平台业务层自动建表/播种，无需手工执行 DDL；本步骤只负责"装好数据库 + 建库建用户"。
> 以下密码均为示例，生产必须替换为强密码。

### 7.1 MySQL 8

Linux（Ubuntu/Debian/麒麟 apt 系）：

```bash
sudo apt-get update && sudo apt-get install -y mysql-server
sudo systemctl enable --now mysql
sudo mysql_secure_installation        # 设置 root 密码、移除匿名用户等

# 建库建用户（业务库 station_platform / 账号 station）
sudo mysql -uroot -p <<'SQL'
CREATE DATABASE station_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'station'@'%' IDENTIFIED BY 'ChangeMe_Strong_Pass!';
GRANT ALL PRIVILEGES ON station_platform.* TO 'station'@'%';
FLUSH PRIVILEGES;
SQL

# 验证
mysql -h127.0.0.1 -ustation -p -e "SHOW DATABASES;"
```

Windows：运行 MySQL Installer 安装 MySQL Server 8（设 root 密码），再用 MySQL Shell/命令行执行同样的建库 SQL。

Docker 快速起库（开发/临时，生产建议用 Compose 内置库）：

```bash
docker run -d --name station-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD='Root@123' -e MYSQL_DATABASE=station_platform \
  -e MYSQL_USER=station -e MYSQL_PASSWORD='Station@123' \
  mysql:8.0 --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
```

### 7.2 PostgreSQL 16

Ubuntu/Debian（PGDG 源或发行版仓库）：

```bash
sudo apt-get update && sudo apt-get install -y postgresql-16
sudo systemctl enable --now postgresql

sudo -u postgres psql <<'SQL'
CREATE USER station WITH PASSWORD 'ChangeMe_Strong_Pass!';

SQL

# 验证
psql -h127.0.0.1 -U station -d station_platform -c "SELECT 1;"
```

Windows：运行 EDB PostgreSQL 16 安装器（设 postgres 超级用户密码），再执行同样的建库 SQL。

Docker 快速起库：

```bash
docker run -d --name station-pg -p 5432:5432 \
  -e POSTGRES_USER=station -e POSTGRES_PASSWORD='Station@123' \

```

### 7.3 Kingbase V8R6（金仓）

金仓通常部署在国产主机（麒麟/统信 x86_64 / arm64）或 Windows，安装包由厂家/项目提供：

```bash
# Linux（以典型路径为例，实际以安装向导为准）
tar -xzf KingbaseES_V8R6_xxx.tar.gz && cd KingbaseES_V8R6_xxx
./setup.sh                          # 图形/命令行向导：选择数据目录、端口（默认 54321）、编码 UTF8

# 以 kingbase 用户初始化并启动
/opt/Kingbase/ES/V8/Server/bin/initdb -D /opt/Kingbase/ES/V8/data -E UTF8
/opt/Kingbase/ES/V8/Server/bin/sys_ctl -D /opt/Kingbase/ES/V8/data start

# 建库建用户（语法兼容 PostgreSQL）
/opt/Kingbase/ES/V8/Server/bin/ksql -U system -d test <<'SQL'
```

Windows：运行 KingbaseES V8 Windows 安装器，服务管理器中启动金仓服务，再用 `ksql` 执行同样的建库 SQL。

### 7.4 连接串与 PROVIDER 对照

| `STATION__DB__PROVIDER` | 连接串示例 |
| :--- | :--- |
| `MySql` | `Server=127.0.0.1;Port=3306;Database=station_platform;Uid=station;Pwd=ChangeMe_Strong_Pass!;Charset=utf8mb4;AllowPublicKeyRetrieval=true;SslMode=None` |
| `PostgreSQL` | `Host=127.0.0.1;Port=5432;Database=station_platform;Username=station;Password=ChangeMe_Strong_Pass!;` |
| `Kingbase` | `Host=127.0.0.1;Port=54321;Database=station_platform;Username=station;Password=ChangeMe_Strong_Pass!;DbType=Kdbndp` |

- Docker 方式：Compose 已固化连接串与库账号，只需改 `.env`；裸机方式用上表；
- 金仓兼容串 `DbType=Kdbndp`：连接失败时优先核对此项与端口（常见问题见第十二章）。

## 八、授权激活流程

1. **内部工具**生成 SM2 密钥对与授权文件：授权内容 = 机器指纹（CPU+主板+磁盘+MAC 的 SM3）+ 到期时间，私钥签名；
2. 采集站首次启动收集本机指纹（Windows=WMI / Linux=sysfs），与授权文件绑定（**一码一机，换硬件即新指纹需重新授权**）；
3. 将授权文件部署到采集站并激活：激活成功后进入正式版（界面徽标）；授权到期瞬间**立即中断进行中的采集**；
4. 平台台账中可查看各站授权状态/剩余天数，到期前预警。

## 九、升级

- **桌面端**：停止进程 → 备份本地数据目录与 `appsettings.json` → 替换发布产物（或运行新版 MSI / `dpkg -i`）→
  启动自检（库结构自动演进：`EnsureColumn` 幂等补列）；
- **平台（Docker）**：停服 → 备份数据库 → `docker compose ... build` → `up -d`（表结构/种子自动初始化）；
- **平台（Windows 裸机）**：停止服务 → 备份数据库与 `appsettings.json` → 替换发布产物（保留配置）→ 启动服务。

> **内网/无网络现场**：平台交付包、数据库安装包、Docker 安装包、离线镜像与证书需提前在有网机器备齐，
> 通过 U 盘/内网共享拷入；具体步骤见分册 04-3（Windows）与 04-4（Docker 离线交付）。

## 十、备份与恢复

- 桌面端本地库：SQLite 文件整体备份/恢复（先停进程或使用备份接口保证一致性快照）；
- MySQL：`mysqldump -ustation -p... station_platform > backup.sql`；恢复先建库再导入；
- PostgreSQL：`pg_dump -U station station_platform > backup.sql`；恢复 `psql -U station -d station_platform < backup.sql`；
- Kingbase：`sys_dump`（金仓自带）同 PostgreSQL 用法；
- 平台 Docker：库数据在命名卷（`mysql-data`/`pg-data`），另有每日自动逻辑备份到 `backups` 卷，
  保留 `BACKUP_RETENTION`（默认 30）份；手动备份/还原见界面"系统管理"；
- 文件数据：采集站缓存目录（`collect-cache`）与存储目标（本地/FTP/SFTP）按策略定期备份；平台仅存元数据。

## 十一、日常运维

- 平台日志：Docker 用 `docker compose ... logs -f api`；Windows 裸机用服务日志（Serilog 文件按天滚动）或事件查看器；
  健康检查统一为 `GET /api/v1/health`；
- 在线率：采集站任意入站请求打心跳，默认 5 分钟超时（`Platform:OnlineTimeoutSeconds` 可调）；
- 报警中心：磁盘不足/网络中断/USB 故障/校验失败/非授权接入/绑定异常/存储不可达/授权到期，界面处置并留审计；
- 记录仪台账：随上报自动归集，生命周期预警（未绑定/非白名单/长期未使用，`Platform:RecorderIdleDays` 默认 30）；
- 存储熔断：上传连续失败达阈值自动熔断（`Station:Storage:CircuitBreakerThreshold`），冷却后自动恢复并补传；
- 平台数据库每日自动备份，定期检查备份卷/目录空间，必要时手动备份留档。

## 十二、常见问题

- **SFTP 上传失败 Permission denied**：确认 `SftpRoot` 指向可写目录（默认登录用户主目录）；端口/账号核对；
- **SFTP 远端大小不一致**：旧版存在尾块丢失（约 1KB），已修复（显式 Flush），升级后重新上传即可；
- **信创机指纹 unknown**：DMI 目录无读权限时回退 unknown，属正常降级；需用 root 读取时以普通用户运行且确保 /sys/class/dmi 可读；
- **金仓连接失败**：确认连接串含 `DbType=Kdbndp`、端口 54321、`STATION__DB__PROVIDER=Kingbase`；
- **平台登录后 1 分钟自动退出**：桌面端空闲登出策略（`Station:Auth:AutoLogoutMinutes`），可配置为 0 关闭；
- **前端白屏**：确认发布产物包含 wwwroot（0.1.0 起已修复），访问 `/` 应返回 Vue 入口；
- **Windows 服务启动失败/超时（1053）**：先在控制台前台启动定位错误（配置、端口占用、权限），确认服务账号对产物目录有读写权限；
- **Windows 裸机 PDF 中文乱码**：Windows 自带中文字体一般正常；异常时设置 `STATION__EXPORT__FONTFILE` 指定字体文件；
- **Linux 桌面端打不开**：按 4.4 安装图形库与字体后重试；确认有图形会话（`echo $DISPLAY` / Wayland）。
